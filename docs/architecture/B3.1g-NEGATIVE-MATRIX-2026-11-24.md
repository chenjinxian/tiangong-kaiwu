## 1. 目标与非目标

### 1.1 目标

1. 把 B3.1c/d/e/f/f-a 以来分散在多个仓库的负例证据收敛为一个**可重复、可审计**的矩阵：
   admin / Editor / Viewer / read-only / outsider / anonymous / signed service scope /
   legacy API-key-only / cross-iTwin，覆盖 Hub 路由、MS 读写与危险表面、BFF 拒绝保留、
   WA 与 storage/tile。
2. 提供两种可执行模式：
   - `--check`（默认）：**不读 secret、不联网**的静态校验；可加 `--run-tests` 执行被引用的
     单元测试；
   - `--probe`：显式提供 probe 配置后对隔离栈发真实 HTTP 请求，记录**精确请求/响应状态**。
3. 报告同时输出 JSON 与 Markdown，每格带 `pass|fail|unproven`、coverage 类别、证据引用、
   期望值与（probe 模式下的）实际观测值。
4. 对未实现/未验证的能力**如实保持 unproven**，不得用“测试绿”冒充“真栈已证明”。

### 1.2 非目标

- 不新增/修改任何生产授权逻辑、Guard 顺序、路由元数据、错误码或配置开关。
- 不做 live DB 迁移、不部署镜像、不跑生产栈、不跑浏览器或 WebSocket 负例。
- 不证明“B3 完成”；不关闭 X-21/X-27；不更新 README/索引/能力账本/例外登记（按任务约束）。
- 不把 shared-key 或 service scope 的已知设计边界改写成 ACL 通过。

### 2.3 状态与 coverage

| 字段 | 取值 | 含义 |
|---|---|---|
| `coverage` | `automated` | 有被引用的单元/路由测试；`--run-tests` 时执行并判定 |
| `coverage` | `manual` | 需要部署栈、真实 seeded 角色、浏览器或 secret；check 模式保持 unproven |
| `coverage` | `unproven` | 当前没有实现或没有可执行证据；必须写明 reason |
| `status` | `pass` | **仅当** `--run-tests` 实际执行且所有引用测试文件/测试名通过 |
| `status` | `fail` | 任一引用测试失败、测试名不存在或 probe 状态不符 |
| `status` | `unproven` | 未执行、被跳过、manual 或未实现；**永不计入 pass** |
| `evidenceKind` | `direct` | 测试直接断言该格行为 |
| `evidenceKind` | `composition` | 由“resolver 测试 + guard 测试”组合推导；弱于 direct，报告中保留标记 |

`pass` 不表示生产栈可用：本文件所载证据全部来自本机单元/路由测试（fake Hub、Nest
Testing、supertest、临时目录），没有一条来自 live Hub/MS/BFF/WA/storage/tile。

## 3. 如何运行

### 3.1 静态检查（默认，无 secret、无网络）

```bash
node scripts/b3.1g-negative-matrix.mjs --check --format markdown
```

- 校验：id 唯一、必填字段、surface/principal 覆盖、automated 必须有证据、证据文件与测试名
  必须存在、manual/unproven 必须写原因。
- 私有仓不存在时只产生 warning（`reference not statically verified`），不伪造 pass。
- 退出码：矩阵非法为 1；否则 0。

### 3.2 检查 + 执行被引用单元测试（无 secret）

```bash
node scripts/b3.1g-negative-matrix.mjs --check --run-tests --format both \
  --out artifacts/b31g
```

- 默认从同级 checkout 查找私有仓：
  `../luban-backend/modeling-server`、`../imodelhub-services`、`../luban-backend/webhook-agent`。
- 可用 `--ms-root` / `--hub-root` / `--wa-root` / `--bff-root` 或
  `B31G_MS_ROOT` / `B31G_HUB_ROOT` / `B31G_WA_ROOT` / `B31G_BFF_ROOT` 覆盖。
- 测试使用各自仓库内的 fake server 与测试 fixture secret，**不需要任何真实 token**。
- 输出 `b31g-negative-matrix-report.json` 与 `.md`；stdout 仍按 `--format` 输出报告。
- 退出码：矩阵非法或任一引用测试失败为 1。

### 3.3 Live probe（仅隔离栈；可选需要 token）

```bash
node scripts/b3.1g-negative-matrix.mjs --probe \
  --probe-config /path/to/b31g.probe.json \
  --allow-mutations \
  --format both --out artifacts/b31g-probe
```

Probe 配置（**不要提交真实 secret**）：

| `wa.baseline.service-scope` | WA 只接受共享 `X-API-Key`，无签名 service token、无 iModel/job 绑定（X-21 残余） | 实现 service token + 作业绑定后做隔离栈负例 |
| `storage.nginx.azurite.anonymous` | 当前 compose/nginx 无 gateway `auth_request`；匿名读取是已知缺口 | 实现网关鉴权或签名 URL 后做匿名 probe |
| `storage.sas.replay` | SAS 是 bearer、无用户/会话绑定；无隔离栈与 minted SAS 无法验证重放 | 隔离栈 mint SAS 后跨会话重放 probe |
| `tile.public-url.anonymous` | tile 仍是 public-url + SAS query，MS/nginx 无逐用户鉴权 | 隔离栈 + 浏览器/渲染检查 |

这 8 格由 **4 个 manual**（匿名 iTwin 读、Editor iTwin 写、service scope 跨 iModel、
key-only 内容路由）与 **4 个 unproven coverage**（WA service scope + storage×2 + tile）
组成；均不计入 `pass`，也不得以“其他格已绿”推断它们已覆盖。

## 7. 阻塞项与已知边界

1. **Hub service scope 不绑定单 iModel**：签名 service principal 按路由 scope 放行，不查
   iTwin/iModel ACL。矩阵把它记录为 manual/unproven，而不是“已覆盖”。需要产品或安全明确
   接受，或实现资源绑定。
2. **WA baseline 仅共享 key**：`POST /baseline/process` 的 body 可指定任意 iModel/iTwin，
   没有作业绑定；X-21 未关闭。
3. **storage/tile 匿名面**：当前 compose/nginx 路径没有 gateway 鉴权；tile URL 是 bearer
   SAS。任何“已强制”声明都需要隔离栈 probe + 浏览器证据。
4. **BFF 不是 Hub 的 PEP**：BFF 只终止 `/api` 的 JWT；`/itwins` 等 HUB 前缀原样透传。
   矩阵的 BFF 阳性格只证明“拒绝保留/认证”，不证明 Hub 路由授权在 BFF 被重算。
5. **无 browser/WS 负例**：MS 的 IPC/WebSocket、tile 渲染、WA 事件链未在真实浏览器/WS
   上跑；`ms.read.*` 的单元证据不能替代真栈 canary。
6. **composition 证据弱于 direct**：部分 Hub RBAC 格由 resolver 测试 + guard 测试组合推导，
   不是单一路由测试；harness JSON 的 `evidenceKind` 保留该区别。
7. **未跑 live 栈**：本文件中所有 pass 都来自本机 fake server/单元测试；没有生产 DB、没有
   部署、没有 secret。
