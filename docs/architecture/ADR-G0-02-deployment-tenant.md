# ADR-G0-02：部署形态、租户边界与多租户门禁

> 状态：**Proposed under owner directive 2026-11-24; not ARB-signed**（业主指令下拟制，尚未经 ARB 签字）
> 日期：2026-11-24
> 关联：`G0-DECISION-REGISTER.md`（D0-2 部署/租户）、`G0-EXECUTION-PLAN.md` §4/§6、`09-INDUSTRIAL-TARGET-ARCHITECTURE.md` §0/§5/§6、`10-ARCHITECTURE-HARDENING-PLAN.md` WS-B/B10、WS-E、G3、`ADR-G0-12`、`ADR-G0-14`（G0 计划项）、`ADR-G0-16`
> 影响面：部署拓扑、租户键、RLS、对象存储前缀、KMS、配额、审计、备份/恢复、产品对外口径
> 本 ADR 只冻结部署顺序与租户架构预留，不表示多租户已实现；不含私有源码、密钥、私有路径或 native 构建证据。

---

## 1. 背景与当前事实

1. 目标架构允许近期单租户/私有部署，中期演进到多租户云服务，并要求租户隔离、配额、审计、HA/DR（09 §0）。部署形态不是纯运维细节：它决定 schema、对象键、ACL、备份与合规边界。
2. D0-2 的建议默认是：**单租户先上线，多租户架构预留**；所有表和对象键从第一天带 `tenantId`，不得用 `iTwinId` 临时充当租户。失败判据是“单租户假设写死进 schema/对象键/权限模型”。
3. 当前 `tenantId` 是 **nullable 占位且恒为 `NULL`**；B2/B3 P0 的 handle/OBO/audit/service client 等 schema 只有占位列，决策只做 iTwin 边界。跨租户负例按 B10 记为 **blocked**，不得写成 passed（`EXCEPTIONS.md` X-22；`AIRR-2026-11-23-B2-OBO-B3-ACL.md` §7.7）。
4. 没有 RLS、租户映射、租户级对象前缀、租户级 KMS、配额或跨租户删除/导出；B10 租户隔离未做（`G1-WAVE2-STATUS-2026-11-23.md` §2、§10）。G1 状态中的“B10 无 tenantId”与 X-22 的“nullable 占位、恒 NULL”描述同一事实：**当前不存在可用于授权的租户模型**。
5. 当前是单栈形态，G1/G3 未通过；HA/PITR、对象存储版本化、TLS/KMS、恢复演练等生产控制未闭环（09 §1.1/§12；G1 状态 §2）。因此“单租户先上线”是**顺序决策**，不是当前已达生产就绪。
6. iTwin 是项目/文档边界，不是法律/计费/数据驻留租户；用 iTwinId 充当 tenantId 会把项目共享与租户隔离混为一谈（D0-2、X-22）。
7. 私有化/on-prem 部署与 ACIS/libslvs 分发、出口分类、数据驻留绑定，属于 D0-12/ADR-G0-12 的书面裁决；本 ADR 不批准 on-prem 形态。

---

## 2. 决策

### D-A 部署顺序：单租户受控生产优先

1. **近期部署形态 = 单租户受控生产**：每个部署服务于一个明确租户（专有实例或专有控制面配置），只面向受控客户名单，不开放公开自助注册，不做公开多租户 SaaS 承诺。
2. **“受控生产”不豁免 Gate**：单租户客户上线仍需 G1（会话/身份/账本/ACL）与 G3（HA/DR/发布/安全/运维）通过；在 G3 前只允许内部验证与合成数据，任何含客户数据的试点还须同时满足 ADR-G0-12 的书面市场/驻留/许可决定；不得把“单租户”当作跳过生产控制的理由。
3. **on-prem 不在本 ADR 批准范围内**：其分发权、ACIS/libslvs 姿态、出口分类、更新/支持模式必须先由 ADR-G0-12 的 Product/Legal 书面裁决；当前近期默认是托管单租户/专有部署，而非客户侧打包。
4. 每个环境（dev/staging/prod）必须显式声明其 tenancy mode；缺失或矛盾时启动/部署失败，禁止默认“全局单租户”。

### D-B 租户键与架构预留

5. **租户是独立一等实体**：目标模型为 `Tenant → Project(iTwin) → Document(iModel)`；Tenant 记录 id、状态、区域、KMS 密钥引用、配额与保留策略。iTwinId 不得作为 tenantId，也不得用于租户授权判断（X-22）。
6. **从第一天带租户键**：所有新增平台表、对象存储键、审计行、日志/指标维度、队列消息、备份 manifest 必须携带租户键或可解析的租户映射；新增表/对象前缀不得以“暂时单租户”为由省略。
7. **现有 nullable 占位是债务，不是模式**：`tenantId = NULL` 只表示“尚未建立租户模型”，不得被新代码解释为“全局可见”或“跳过租户检查”。新代码不得把 null 当作通配。
8. **B10 必须交付的租户能力**：租户映射、schema 回填、RLS/查询强制、对象前缀、租户级 KMS/配额、跨租户负例（Hub/MS/BFF/WA/storage/tile/audit）、租户删除/导出与残留检查。B10 未完成前，`tenantId` 不参与授权。
9. **每个入口都是 PEP**：租户上下文必须在 Hub、MS/BFF、WA、storage/tile 与审计入口生效；只在 Hub 查询加过滤而对象存储/tile/WA 仍可跨租户读取，视为未完成。
10. **租户隔离不替代 per-doc ACL**：同一租户内的用户仍需 B3 的 per-document ACL、组/分享与 deny；不得用“同一租户”推导出文档可读/可写。
11. **多租户声明门禁**：在 B10 关闭且 G3 通过之前，任何“多租户 SaaS/跨租户隔离/租户配额已生效”的对外声明、销售材料、SLA 或 UI 文案一律 blocked。B10+G3 之后仍需独立 ADR/ARB 批准共享多租户 SaaS，本 ADR 只做架构预留。
12. **区域与驻留预留**：租户记录必须能表达存储区域、KMS 区域、备份区域与允许的子处理者；具体区域选择与跨境传输由 ADR-G0-12 的书面决定约束，不在本 ADR 预设。

### D-C 暂缓的部署形态

13. 共享多租户控制面、跨区域多活、租户自助开通、按租户计费/配额自动化均后置；不得在 B10/G3 前实现“先共享、后补隔离”的形态。
14. 私有化交付（客户机房）后置，且仅能在 ADR-G0-12 解决分发/许可/出口与 ADR-G0-14 解决客户侧备份/升级后立项。

## 3. 备选方案与拒绝理由

| 选项 | 内容 | 拒绝理由 |
|---|---|---|
| A | 立即做共享多租户 SaaS | 无 tenantId 模型/RLS/前缀/KMS/配额；ACL 与 DR 未闭环；跨租户泄露不可逆 |
| B（本 ADR） | 单租户受控生产优先；租户键与 RLS 架构预留；多租户 claim 待 B10/G3 | 降低首期合规/运维复杂度，同时避免后补租户键导致 ACL/存储/备份迁移 |
| C | 同时支持单租户与多租户双形态 | 测试/合规/运维面翻倍；无 staging/IaC 与多租户证据；无法在 G1/G3 前验证 |
| D | 单租户且不引入 tenantId，等做多租户时再加 | 后续要迁移所有表、对象键、ACL、审计、备份；违反 D0-2 失败判据 |
| E | 用 iTwinId/iTwin account 充当 tenantId | iTwin 是项目/文档边界，不是法律/计费/驻留租户；会把项目共享误当租户隔离 |
| F | 保留 tenantId 列但只做标签，不做 RLS/PEP | 制造“有租户列所以已隔离”的假象；X-22 明确禁止用于授权 |
| G | 先做 on-prem 私有化，再考虑托管 | libslvs GPL/ACIS 分发/出口未裁决；on-prem 打包当前是 stop-ship（X-08、ADR-G0-12） |
| H | 单租户即不需要 per-doc ACL | 同租户内仍有非成员/只读/分享/撤销；租户边界不能替代文档 ACL |

## 4. 后果与风险

### 正向

- 首期部署与合规复杂度较低；G1/G3 完成后，单租户客户可按专有实例交付。
- 租户键、KMS、对象前缀从新代码开始预留，避免 B10 时全量迁移。
- 多租户对外声明有明确门禁，降低跨租户泄露与合规事故风险。

### 负向/成本

- 每张表/每个对象键/每条审计都要带租户维度，增加 schema 与查询复杂度。
- RLS/前缀/KMS/配额需要真实 Postgres 与对象存储环境验证；Azurite 单栈不能证明生产形态。
- 单租户专有部署仍有较高运维 toil；多租户 SaaS 并不会因为“预留”而自动可用。
- 区域/驻留决策未定前，租户模型只能预留，不能承诺具体区域。

### 主要风险

| 风险 | 触发 | 缓解 |
|---|---|---|
| 假租户安全 | tenantId 有列但不参与授权；跨租户负例未跑 | X-22 保持 open；B10 前禁止租户授权；负例 blocked 不得写 passed |
| 单租户被用来跳过 ACL | 以“只有一个租户”为由关闭 B3/per-doc ACL | 明确租户 ≠ 文档权限；G1 Gate 仍要求非成员 403 |
| 存储/tile/WA 旁路 | Hub 查询有租户过滤，但对象前缀/tile/WA 无 | 每入口 PEP；跨租户负例覆盖 storage/tile/WA |
| 回填污染 | 未知租户被默认写成一个“全局租户” | 未知映射 fail closed/隔离，不默认填充 |
| 区域错配 | 数据/备份/日志落在未批准区域 | 租户区域字段 + 部署检查；ADR-G0-12 书面区域决定 |
| 多租户过早承诺 | 商业压力下宣称“已支持多租户” | 本 ADR + 能力账本 + 发布门双重阻断 |
| 单实例租约/会话 | 多实例部署但 C5 未实现 | 单实例限制写入 ADR/配置；多实例前完成 C5/X-06 退出 |

## 5. 迁移、回滚与失败判据

### 迁移阶段

1. **S0（当前）**：tenantId nullable 占位、恒 NULL；只做 iTwin 边界；跨租户负例 blocked（X-22）。
2. **S1（B10 schema/回填）**：additive 增加租户/区域/KMS/配额字段与映射表；按部署配置回填单一租户；未知映射 fail closed；dry-run + 旧库 fixture。
3. **S2（shadow 校验）**：所有入口计算租户上下文并记录不一致，不拒绝；验证映射覆盖率与对象前缀缺口。
4. **S3（enforce）**：RLS/查询强制、对象前缀、KMS、配额、跨租户负例全拒；开始租户删除/导出演练。
5. **S4（G3）**：HA/PITR、对象版本化、TLS/KMS、DR 演练、发布门通过后，才允许单租户受控生产。
6. **S5（多租户）**：B10+G3 后另立 ADR/ARB，评估共享控制面、跨区域与计费；不在本 ADR 自动生效。

### 回滚

- 租户强制开关可回退到“单租户专有模式”，但**不得**回退到“tenantId 为 null 且跳过租户检查”的隐式模式；回退必须显式声明单租户部署并保留租户键。
- 对象前缀迁移采用双读/复制校验/切换；回滚保留旧前缀，不删除已复制数据。down 迁移只移除策略/索引，不删除租户值；存在混合/未知租户时 down 必须 fail closed。
- 若 B10 回填错误：停止写入、隔离受影响租户、从备份恢复；不得用“重新打标签”掩盖跨租户可见性。

### 失败判据

1. B10/G3 前对外宣称多租户 SaaS、跨租户隔离、租户配额或“租户安全”。
2. 在 tenantId 为 NULL/占位时用其做授权判断，或把 iTwinId 当 tenantId。
3. 新增表/对象前缀未带租户键，或新代码把 NULL 当作通配。
4. 跨租户负例被写成 passed 而没有真栈证据；或只测 Hub 不测 MS/WA/storage/tile/audit。
5. 单租户生产跳过 G1/G3，或以“私有部署”为由使用 dev 默认密钥/Azurite/无 TLS。
6. 租户删除后仍有对象/备份/日志残留，或无法导出/删除客户数据。
7. 未做书面区域/驻留决定即在多区域存储客户模型（同时触发 ADR-G0-12 失败判据）。

任一触发时：停止租户开通/对外声明，安全与数据 owner 复核，回到 B10/G3 或 ADR 修订。

- **D0**：D0-2（本 ADR）、D0-12（区域/驻留/出口）、D0-14（DR/HA）、D0-16（真实归因，跨租户审计依赖）。
