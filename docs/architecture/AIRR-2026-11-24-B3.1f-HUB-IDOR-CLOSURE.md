## 1. 目标与验收

### 1.1 目标

1. **access-control 子资源父绑定**：`/accesscontrol/itwins/:id/...` 的每个子资源
   （roles、user/owner members、groups、group members、invitations、shares、jobs）
   在读取或变更前必须证明该子行属于路径 `:id`；跨 iTwin 子 ID 一律 404。
2. **图片删除归属**：`DELETE /itwins/:id/image/:imageId` 在删除前校验 image 行
   的 `iTwinId === :id`，跨 iTwin 404。
3. **favorites/recents 写 ACL**：`POST /itwins/favorites/:id`、`POST /itwins/:id/favorite`、
   `POST /itwins/recents/:id`、`POST /itwins/:id/recents` 要求路径 iTwin 的
   `itwins_webview`；无权限 403。
4. **favorites/recents 列表过滤**：`GET /itwins/favorites`、`GET /itwins/recents`
   及 `/list` 兼容别名逐项经 `AuthorizationService.getPermissions` 过滤，
   只返回仍有 `itwins_webview` 的 iTwin。
5. 不改成功路径的响应契约（除下述删除不存在子行的状态码，见 §6.1）。

### 1.2 非目标

- 不重构 repository 接口，不新增 scoped `findById`；绑定在 service 层完成。
- 不修改既有 `@RequirePermission`/`ResourceAccessGuard`/`SystemAgentOrResourceGuard` 语义。
- 不扩大 `AUTHZ_ENFORCE` 覆盖，不关闭 X-27；原有 46 条路由例外中仅关闭 4 条 favorites/recents 写，当前仍余 43 条。
- 不处理 iModels 级 favorites/recents、files、baseline/admin、webhooks、repositories。
- 不新增审计表/事件，不改 webhook 载荷。
- 不跑 live DB / 真实栈；本切片证据为单元测试 + `tsc` + ESLint。
- 不改 public README/index/能力账本/例外登记（由后续集成统一更新）。

## 3. 语义与路由矩阵

### 3.1 子资源绑定（404）

| 路由组 | 方法（示例） | 绑定的子资源 | 变更前 | 变更后 |
|---|---|---|---|---|
| roles | GET/PATCH/DELETE `:id/roles/:roleId` | role.iTwinId | 只看 `:id` 权限，按 `roleId` 直接读写 | 先查 role，不属于 `:id` → 404 |
| user members | GET/PATCH/DELETE `:id/members/users/:memberId` | member.iTwinId | 已是 scoped（`getUserMember`） | 不变 |
| owner members | DELETE `:id/members/owners/:memberId` | ownerMember.iTwinId | 按 `memberId` 直接删 | 先查行，跨 iTwin → 404 |
| groups | GET/PATCH/DELETE `:id/groups/:groupId` | group.iTwinId | 按 `groupId` 直接读写 | 先查行，跨 iTwin → 404 |
| group members | POST `:id/members/groups`（body `groupId`） | group.iTwinId | body `groupId` 未绑定路径 iTwin | 绑定后 404 |
| group members | GET/PATCH/DELETE `:id/members/groups/:groupId...` | group.iTwinId | 按 `groupId` 直接读写 | 先查行，跨 iTwin → 404 |
| group invitations | GET `:id/groups/:groupId/invitations` | group.iTwinId | repository 按 iTwin 过滤，跨 iTwin group 返回空列表 | 先查 group，跨 iTwin → 404 |
| group invitations | DELETE `:id/groups/:groupId/invitations/:invitationId` | group + invitation | 忽略 `:id`/`:groupId`，按 invitationId 直接删 | 两者均绑定路径 iTwin，任一跨 iTwin → 404 |
| invitations | GET/DELETE `:id/members/invitations/:invitationId` | invitation.iTwinId | 按 invitationId 直接读写 | 先查行，跨 iTwin → 404 |
| shares | GET/DELETE `:id/shares/:shareId` | share.iTwinId | 按 shareId 直接读写 | 先查行，跨 iTwin → 404 |
| jobs | GET `:id/jobs/:jobId`、GET `:id/jobs/:jobId/actions` | job.iTwinId | 按 jobId 直接读；不存在返回空 actions | 先查行，跨 iTwin/不存在 → 404 |

### 3.2 图片删除

`DELETE /itwins/:id/image/:imageId`：`itwins_modify` 仍由 `ResourceAccessGuard`
在路径 `:id` 上判定；service 再校验 `image.iTwinId === :id`。不存在或跨 iTwin
均 404，不落到 `removeImage(imageId)`。

### 3.3 favorites/recents

| 路由 | 变更 |
|---|---|
| `POST /itwins/favorites/:id`、`POST /itwins/:id/favorite` | 新增 `@RequirePermission(ITWINS_WEBVIEW, { itwinParam: 'id' })` + `ResourceAccessGuard`；无权限 403 |
| `POST /itwins/recents/:id`、`POST /itwins/:id/recents` | 同上 |
| `DELETE /itwins/favorites/:id`、`DELETE /itwins/:id/favorite` | **保持 JWT-only**：用户必须能在失去访问后清理自己的陈旧收藏；删除只作用于 user-owned 行 |
| `GET /itwins/favorites`、`/favorites/list`、`GET /itwins/recents`、`/recents/list` | handler 逐项 `getPermissions`，仅保留含 `itwins_webview` 的 iTwin |

## 6. 风险、残余与产品决策

### 6.1 已发生的非成功路径行为变化

1. **DELETE 不存在/跨 iTwin 子行由幂等 204 改为 404**：roles、owner members、groups、
   invitations、shares、jobs actions 均按 scoped lookups 的“不可区分”语义处理。
   成功删除同 iTwin 子行仍为 204。若产品要求保留幂等 204，需要另行决定，并接受
   “跨 iTwin 404 vs 本 iTwin missing 204”的存在性 oracle。
2. **`GET /itwins/:id/jobs/:jobId/actions` 对不存在 job 由 200 `{actions: []}`
   改为 404**：与其余子资源 GET 一致；成功 job 的 actions 不变。
3. **favorites/recents 写从“任意已认证用户可写”收紧为 `itwins_webview`**：
   仅持有 iModel share、但非 iTwin 成员/创建者的用户不能再收藏该 iTwin。
   这是关闭写 IDOR 的直接结果，也是产品需确认的口径。

### 6.2 残余（本切片不修）

1. **列表分页过滤的页边界**：GET favorites/recents 先按 `$skip/$top` 取原始页，
   再逐项过滤；`_links.next` 仍按过滤后的 `result.length === $top` 判断。
   被过滤项较多的页可能少返回且提前停止翻页。无 schema/接口变更的前提下，
   需要 repository 返回 raw-page-full 信号才能彻底修复。
2. **repository 未 scoped**：子资源仍用无作用域 `findById` + 服务层比较；
   未来若新增直接调用 repository 的路径，需要重复绑定或改接口。
3. **group invitation 删除只绑定 iTwin**：未校验 invitation 的 `groupIds`
   是否包含路径 `:groupId`。同 iTwin 内跨 group 路径删除不构成跨租户授权提升，
   但路径语义不严格。
4. **owner/user member 的通用方法仍 unscoped**：`updateUserMember(id)` /
   `removeUserMember(id)` 供 `iTwinMembersService` 在已做 iTwin 绑定的门面内使用；
   access-control REST 已走 scoped 变体。
5. **图片删除不清理对象存储 blob**：既有行为；DB 行删除后可能留下孤儿 blob。
6. **favorites/recents 列表无路由级 PEP**：handler 过滤属 X-27 例外，X-27 仍 open。
7. **未覆盖 iModels favorites/recents**：本次只处理 iTwin 级。
8. **未做 e2e/真实栈**：按任务约束仅单测；无跨服务 canary。

### 6.3 待产品/UX 决策

- 收藏/最近访问写是否应对“仅有 iModel share”的用户开放（当前拒绝）。
- DELETE 子资源不存在时保留幂等 204 还是统一 404。
- 过滤列表的分页语义：接受少返回/提前结束，还是改接口暴露 raw-page-full。
