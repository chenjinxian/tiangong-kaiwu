## 1. 目标、验收与非目标

### 1.1 目标

1. 给 modeling-server 增加一个**显式读强制模式**：`AUTH_B3_READ_MODE=enforce`。
2. 强制只使用既有 OBO shadow 传输（delegation handle → 单 iModel OBO → Hub decision），不建第二套策略引擎、不改 Hub 契约。
3. 在四个读入口（`downloadBriefcase`、`openBriefcase`、`openCheckpoint`/`downloadVersionBriefcase`）与 FeatureOp 读方法上，先同步取得 Hub 对**精确动作集合**的决策，全部 allow 才继续 legacy 操作。
4. 默认 `off` 时保持 legacy/shadow 行为逐字不变；回滚只需改回 `off`，无数据/schema 迁移。

### 1.2 可观察验收

- `off`（默认）：现有 shadow observe、legacy 下载/打开/读树行为不变；`pepCoverage` 状态更新为 enforce-capable，但不产生新 Hub 调用。
- `enforce`：
  - readonly `downloadBriefcase`/`openBriefcase` 仅要求 `doc.read`；rw 要求 `doc.read` **且** `briefcase.write`。只读用户请求 rw 得到 `AuthorizationDenied` 403，且不产生 briefcase 预留/下载/打开。
  - `openCheckpoint`/`downloadVersionBriefcase`/read-only 版本打开要求 `doc.read`，并在 Hub resolver/下载之前完成。
  - FeatureOp 读（`listPartStudios`、`getFeatureTree`、`getSketch`、`listSketches`、`getVariables`、`getMassProperties`、`getBodies`、`resolveEdgeRef`、`resolveFaceRef`）要求 `doc.read`，且在 `getFeatureService`/`ensureInitialized` 之前完成；被拒调用者不能触发 rebuild。
  - `getFeatureFormModel` 无文档键，**不强制**。
  - 无 session、无 iTwin/iModel、无 handle、Hub 超时/不可用、决策 deny → fail closed。绝不回退共享 key/JWT、绝不继续 legacy。
  - 决策按 session/iModel/动作集合缓存（Hub TTL 上限 30s），读树不会每方法回源 Hub。
  - 首个读在 WS 升级 handle 签发完成前到达时，gate 等待在途 provisioning（有界），不会误拒。
- 错误面新增稳定 `SessionError` 码：`AuthorizationDenied`（403）、`AuthorizationUnavailable`（503）；消息只含稳定 reason/code，不含 token/handle/OBO/请求体。

### 1.3 非目标（本切片明确不做）

- 不强制写：`applyFeatureOp`/`previewFeatureOp`/PartStudio create/rename/delete、`saveChanges`/`pushChanges`/`pullChanges`/`abandonChanges`、直改 `basicManipulationIpc`/`solidModelingIpc`、`exportIModel`（B3.1d+）。
- 不改 Hub 路由 guard/controller（B3.1e）；不做 Hub 数据面 OBO、BFF/WA/storage/tile/progress/retry。
- 不改 shared IPC/RPC 契约；不 bump `@luban-cad/shared`；不改 web/viewer。
- 不做 B4 groups/shares 新语义（Hub B3.1b 已实现 resolver，但本切片只消费决策）、B6 服务身份退役、B10 租户、B7 WORM。
- 不新增 token/audit 表、不迁移数据；不实现 WS ticket/长会话续期。

## 2. 复用矩阵

| 能力 | 现有实现 | 本切片决策 | 理由 |
|---|---|---|---|
| 用户委托 | `SessionRecord.oboShadow` delegation handle（B2 P0） | 复用 | 已有 WS 升级签发、关闭撤销、无用户 token 落盘 |
| OBO 交换 | `OboShadowClient.exchangeObo` | 复用，缓存键改为 iModel+scope 集合 | 防止 read token 被 rw 决策复用 |
| 决策 | Hub `POST /internal/v1/authz/decisions` + `AuthorizationService` | 复用 | 单一 PDP；MS 不做本地策略 |
| 决策缓存 | `SessionRecord.oboShadow.decisions` | 复用，key=`iModel+排序动作集` | 读写 TTL 由 Hub 返回（≤30s），无需新缓存 |
| 入口 | `LubanIpcHandler` / `AppFunctionIpcHandler` / `VersionOpenService` / `LubanFeatureRpcImpl` | 加薄 gate | 保持所有权/路径/租约检查与顺序 |
| 错误 | `SessionError` 码 | additive 两码 | 客户端可分支；消息不泄密 |
| 覆盖清单 | `pepCoverage` v3 | 5 个读入口 `covered-enforce` | 不把写/未实现入口误标为已强制 |

**规则**：`ReadAccessGate` 只做动作映射和 fail-closed 适配；handle/OBO/decision/记录仍全部在 `OboShadow` 内，`observe` 与 `authorize` 共用同一实现。

## 3. 开关、启动校验与回滚

| 变量 | 默认 | 允许值 | 说明 |
|---|---|---|---|
| `AUTH_B3_READ_MODE` | `off` | `off`/`enforce` | 唯一读强制开关；`off` 是回滚 |
| `AUTH_OBO_MODE` | `off` | `off`/`shadow` | `enforce` 时必须是 `shadow` |
| `AUTH_OBO_SERVICE_NAME` | 无 | Hub allowlist 内名称 | `enforce` 时必填，且须与 Hub 一致 |
| `AUTH_OBO_HTTP_TIMEOUT_MS` | `2000` | 100–10000 | 单次 Hub 调用上限；gate 等待 provisioning 的上限在此基础上 +1s |

启动校验（`config.ts` `superRefine`）：

- `AUTH_B3_READ_MODE=enforce` 且 `AUTH_OBO_MODE!=shadow` → 启动失败并点名 `AUTH_B3_READ_MODE`。
- `enforce` 且缺 `AUTH_OBO_SERVICE_NAME` → 启动失败并点名 `AUTH_OBO_SERVICE_NAME`。
- service-token 模式的 client id/secret 校验沿用既有规则；无静默降级。
- 启动日志明确输出 `AUTH_B3_READ_MODE=enforce` 与回滚方式（不打印 token/secret），`off` 也输出未强制状态。

**回滚**：设置 `AUTH_B3_READ_MODE=off` 并重启。无数据/schema 迁移；Hub 已写 audit 保留；handle/OBO 自然过期（15m/5m）。不自动恢复已撤销 session。

| 入口 | 方法/绑定 | enforce 动作 | gate 位置 | off/shadow |
|---|---|---|---|---|
| IPC download | `LubanIpcHandler.downloadBriefcase` | readonly=`doc.read`；rw=`doc.read`+`briefcase.write` | id 校验后、reserve/download 前 | legacy；shadow fire-and-forget 观察不变 |

| IPC checkpoint | `AppFunctionIpcHandler.openCheckpoint` → `downloadLatestReadOnly`/`downloadReadOnly` | `doc.read` | Hub resolver/下载前；随后 open 复用决策缓存 | legacy D5 不变 |
| FeatureOp 读 | `LubanFeatureRpcImpl` 九个读方法 | `doc.read` | `getFeatureService`/`ensureInitialized` 前 | legacy；无 shadow 观察 |
| FeatureOp 表单 | `getFeatureFormModel` | 不强制 | — | legacy（无文档键） |

- 写入口完全未改；`AUTH_B3_READ_MODE=enforce` 不改变任何写路径。

## 5. 判定语义、Deny 优先级与错误面

```text
AUTH_B3_READ_MODE=off → legacy（零 gate 调用）
enforce:
  1. 无 session → AuthorizationDenied
  2. 无 iTwinId/iModelId → AuthorizationDenied
  3. 等待在途 handle provisioning（≤ Hub 超时 +1s）；失败 → AuthorizationUnavailable（记录稳定 code）
  4. 无 handle / handle 过期/用尽 / session 撤销 → AuthorizationUnavailable
  5. 换 OBO 或 Hub decision 超时/5xx/网络/非法响应 → AuthorizationUnavailable
  6. Hub decision allow=false，或任一请求动作 != allow → AuthorizationDenied
  7. 全部动作 allow → 继续 legacy
```

- 只允许“决策允许**全部**请求动作”才放行；aggregate allow 但 action map 有 deny 也按 deny 处理（稳定 reason `insufficient_permission`）。
- 不重试共享 key/JWT，不因 deny 继续 legacy，不把 deny 写成 legacy continuation。
- 记录（内存有界）与日志字段只有：entry、iModelId、actions、decision、reason、decisionId、granted/denied scopes、稳定 code/status、`mode=enforce`（shadow 记录形状不变）。不含 token/handle/OBO/decision 请求体。

| 错误码 | HTTP | 触发 |
|---|---|---|
| `AuthorizationDenied` | 403 | 缺 session/文档上下文；显式策略 deny；只读用户请求 rw |
| `AuthorizationUnavailable` | 503 | handle 缺失/过期/用尽、provisioning 失败、Hub 超时/不可用/非法响应 |

## 6. OBO 正确性与决策缓存

### 6.1 按 scope 集合缓存 OBO

旧实现按 iModel 单键缓存：先为 `doc.read` 换到的 token 可能被后续 `doc.read+briefcase.write` 决策复用。B3.1c 改为：

- OBO cache key = `${iModelId}|${actions.sort().join(',')}`；
- 命中时还必须 `grantedScopes` 覆盖全部请求动作，否则重新 exchange；
- 每个缓存项保留 `iModelId`，终止失败/关闭时按文档清理全部 scope 项；
- 新 OBO 产生后清除该 iModel 的旧 decision 缓存（避免旧 claims 结果）。

因此 read → rw 一定得到包含 `briefcase.write` 的新 OBO（或由 Hub 拒绝/部分授予，随后决策 deny）。

### 6.2 决策缓存

- key = `${iModelId}|${actions.sort().join(',')}`（精确动作集合）。
- TTL = Hub 返回 `cacheTtlMs`，上限 30s；写决策的 5s TTL 由 Hub 返回，MS 不延长。
- 同一 session/iModel/`doc.read` 的多次 FeatureOp 读只回源一次 Hub；expired 后重新决策。
- 无新增无界缓存；session 关闭清空 handle/OBO/decisions。

### 6.3 WS 升级 provisioning 竞态

WS 升级以 fire-and-forget 方式换 handle；enforce 读可能先到。处理：

- `provisionSession` 同步创建并挂载 `state.provisioning` Promise；
- `authorize` 先等待该 Promise（上限 `AUTH_OBO_HTTP_TIMEOUT_MS + 1000ms`），再取 handle；
- provisioning 仍失败/超时 → 记录稳定 code（`provisioning_timeout` 或上游 code）并 `AuthorizationUnavailable`；
- shadow 路径不等待、不改变行为；连接在签发完成前关闭则不保留/尽力撤销 handle。

## 9. 残余风险与边界

1. **handle 15m 上限**：enforce 下 handle 过期后读返回 `AuthorizationUnavailable`，直到重连换新 handle；P2 前需 WS ticket/续期流程。
2. **决策缓存窗口**：Hub 读决策 TTL 可到 30s，角色撤销在该窗口内仍可能 allow；B3.1c 不放宽 Hub TTL。
3. **首次读延时**：每个 (session,iModel,动作集) 的首次读同步等待 exchange+decision；后续命中缓存。未测 p95。
4. **B6/X-21 未关闭**：OBO 决定用户身份，但内部 exchange/decision 传输在 legacy 模式仍用共享 key + 服务账号 JWT；不得宣称服务身份分离完成。
5. **B4/B10**：隔离 canary 覆盖了 View share 与 outsider 的 allow/deny；仍无 live ACL 数据、组/denyList/过期 share 的 MS 侧 canary；跨租户仍 blocked。
6. **Open 入口身份来源**：enforce 要求已注册/已打开 db 的 iModel/iTwin；legacy 未注册文件的打开会 403，属预期 fail-closed，需要在 canary 评估客户端流程。
7. **FeatureOp 读**：依赖 db 已打开且带 iTwinId；standalone/Guid.empty 会被拒绝。
8. **路由级与写强制未做**：Hub 路由仍 legacy；MS 写/直改/save/push/export 仍未受 per-doc ACL（B3.1d+）。B3/X-21 仍 open，G1 Gate 不勾选。
