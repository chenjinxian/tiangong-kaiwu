## 1. 目标、可观察验收与非目标

### 1.1 目标

1. 为 B3.1f 审计中的危险非 IPC 表面增加一个显式开关
   `AUTH_B3_SURFACES_MODE=off|enforce`（默认 `off`），使现有行为在 canary 前保持不变。
2. `enforce` 时 `LubanRpcImpl.exportIModel` 必须经既有 B3.1c 读 gate/OBO 传输取得
   **`doc.read`** 决策；文档身份（iTwinId）只取服务端已打开 db，绝不取 RPC 参数。
3. `enforce` 时 `GET /api/imodels/:id/progress`（设计动作 `doc.read`）与
   `POST /api/imodels/:id/retry`（设计动作 `doc.manage`）在无 session-bound OBO 传输可绑定的
   前提下**默认关闭 fail-closed**：无 token 仍 401，有 token 直接 403，且不调用 Hub `/auth/me`、
   不读 progress map、不校验 iTwinId、不以服务凭据调用 HUB requeue。
4. BFF 必须原样保留 MS 的 401/403（状态码 + body），不得重试、不得替换为成功；不得把
   service 凭据升级为用户身份。
5. 默认 `off` 时零新 Hub 调用、零新拒绝、零行为变化；回滚=改回 `off` 并重启，无数据/schema 迁移。
6. 对 undo/close/assembly/saved views 等未覆盖表面**如实记录为残余**，不冒充已覆盖。

### 1.2 可观察验收

- `off`（默认）：export/progress/retry 与 `pepCoverage` v5 之前行为逐字一致；现有测试不变。
- `enforce`：
  - export 在 `doc.read` allow 后才执行导出查询；deny→403 `AuthorizationDenied`，
    decision 不可用→503 `AuthorizationUnavailable`；无 session、db 未打开、standalone/snapshot
    （`Guid.empty` iTwinId）或 db 无 iTwinId → 403，且不调用 `withPreparedStatement`/不返回模型内容。
  - progress：缺 Authorization → 401；有 Authorization（无论 Hub 是否接受）→ 403
    `AuthorizationDenied`（`progress_surface_unbound`），`/auth/me` 调用数 0，progress map 读取 0。
  - retry：缺 Authorization → 401；有 Authorization → 403（`retry_surface_unbound`），
    `/auth/me` 0、iTwinId 校验 0、HUB requeue 0；服务凭据不离开进程。
  - BFF：上游 403/401 状态码与 body 原样返回，MS 仅被调用一次；不存在“重试后 200”或
    “拒绝后仍返回成功”。
- 启动校验：`AUTH_B3_SURFACES_MODE=enforce` 且 `AUTH_B3_READ_MODE!=enforce` → 启动失败并点名
  `AUTH_B3_SURFACES_MODE`（避免“声称强制、实际无 ACL 的 legacy export”）。
- 错误/日志只含稳定 code/reason/entry/iModelId；不含 token/handle/OBO/Authorization/secret。

### 1.3 非目标（本切片明确不做）

- 不为 progress/retry 发明“无 session 的用户身份”：不把 bearer 直接当 OBO、不按 userId 猜
  某个 WS session、不引入每请求 handle 签发（需产品/传输决策，见 §9）。
- 不改 Hub 路由/guard/PDP；不改 retry 的 service-account 通道与用户归因（X-21）；不实现
  `requestedBy=user` 的 Hub 用户 retry 路由。
- 不覆盖 undo/redo/reverseTxns、`toggleGraphicalEditingScope`、`closeIModel`、
  assembly helpers、saved views/camera paths；保持 `p0-not-covered`（§6）。
- 不覆盖 tile/storage/SAS、`/ws` progress 推送授权、WA baseline、Hub 数据面命名版本/checkpoint。
- 不做 export 的审计/HITL（P0-10 敏感操作的产品决策）、不做每 session briefcase 所有权
  （本切片只做 per-user `doc.read` + 活跃 session 前置）。
- 不跑真栈 canary、live DB、迁移、镜像发布；不改 docs 索引/README/例外登记（由后续集成统一更新）。

## 3. 开关、启动校验、日志与回滚

| 变量 | 默认 | 允许值 | 本切片要求 |
|---|---|---|---|
| `AUTH_B3_SURFACES_MODE` | `off` | `off`/`enforce` | 唯一危险表面开关；`off` 是回滚 |
| `AUTH_B3_READ_MODE` | `off` | `off`/`enforce` | `surfaces=enforce` 时**必须** `enforce`（export 复用读 gate） |
| `AUTH_OBO_MODE` | `off` | `off`/`shadow` | 由 `AUTH_B3_READ_MODE=enforce` 的既有校验要求 `shadow` |
| `AUTH_OBO_SERVICE_NAME` | 无 | Hub allowlist 内名称 | 同上，必须显式且与 Hub 一致 |
| `HTTP_STATEFUL_RPC_MODE` | `deny` | `deny`/`allow` | 建议保持 `deny`；`allow` 时启动告警（HTTP RPC export 无 SessionContext→403） |

启动校验（`src/config.ts` `superRefine`）：

- `AUTH_B3_SURFACES_MODE=enforce` 且 `AUTH_B3_READ_MODE!=enforce` → 启动失败，错误路径点名
  `AUTH_B3_SURFACES_MODE`，消息说明 legacy export 无 ACL，不允许静默降级。
- 其余 OBO shadow/service name 组合由既有 B3.1c/B3.1d 校验覆盖，不重复放宽。

启动日志（`src/main.ts`）：

- `enforce`：WARN 输出 export 的 `doc.read`、progress/retry 的 403 `surface_unbound`、deny 前置
  边界与回滚方式；`HTTP_STATEFUL_RPC_MODE=allow` 时额外 WARN export 会 403。
- `off`：INFO 明确 legacy（export 无 ACL；progress/retry 只认证）。
- PEP 摘要增加 `fail-closed=[progress, retry]`，并在 `covered-enforce` 列表中显示 `exportIModel`。

**回滚**：`AUTH_B3_SURFACES_MODE=off` 并重启。无数据/schema 迁移；进程重启清空 handle/OBO/
decision 缓存；Hub 已写 audit 保留。配置只在启动读取，不支持运行时翻转。

## 4. 入口/动作/顺序矩阵

| 入口 | 绑定 | enforce 动作 | gate 位置（先于任何副作用） | `off` |
|---|---|---|---|---|
| 导出 | `LubanRpcImpl.exportIModel` | `doc.read`（经 B3.1c 读 gate/OBO） | 解析已打开 db 的 iTwinId 后、`exportToGltf`/`withPreparedStatement` 前；无 session/db/非 iTwin → 403 | legacy 无 ACL 导出 |
| 进度 | `GET /api/imodels/:id/progress`（`routes/progress.ts`） | 设计=`doc.read`；本切片不做决策 | 缺失 token 401 之后、Hub `/auth/me`/progress map 之前 → 403 `progress_surface_unbound` | legacy `/auth/me` + 内存进度 |
| 重试 | `POST /api/imodels/:id/retry`（`routes/retry.ts`） | 设计=`doc.manage`；本切片不做决策 | 缺失 token 401 之后、`/auth/me`/iTwinId 校验/HUB requeue 之前 → 403 `retry_surface_unbound` | legacy `/auth/me` + 服务凭据 requeue |

**顺序不变量**

1. 认证先于授权：缺 Authorization 一律 401，且此检查无 Hub/DB/文件副作用。
2. `enforce` 的表面拒绝发生在任何 Hub 调用、db 查询（export 的 `tryFindByKey` 仅用于取得
   服务端身份，是只读注册表查找）、progress map 读取、briefcase 文件访问、requeue 写之前。
3. export 的 iTwinId 只来自 `IModelDb.iTwinId`；RPC 只有 `iModelId`，**不接受**客户端 iTwinId。
4. `AUTH_B3_SURFACES_MODE=off` 时 export 不增加任何查找/session 要求；progress/retry 走原逻辑
   逐字不变。
5. deny 不得写 no-op 成功、不得回退服务账号/共享 key、不得继续 legacy。

**注意**：单一开关使 `enforce` 同时关闭 export 的 legacy 与 progress/retry 表面。这是审计要求的
“危险表面 fail-closed”语义；在 progress/retry 传输决策完成前，启用该开关会使这两个路由 403，
canary 必须把这一行为当作预期而不是回归。

## 5. 判定语义与错误面

```text
AUTH_B3_SURFACES_MODE=off → 全部 legacy（零新 Hub 调用；export 无 ACL）

enforce:
  exportIModel:
    1. 无已打开 db / db 无 iTwinId / Standalone/Snapshot(Guid.empty) → AuthorizationDenied 403
    2. 无活跃 session → AuthorizationDenied 403
    3. 读 gate 未启用（配置被绕过）→ AuthorizationUnavailable 503
    4. 等 handle provisioning/OBO exchange/Hub decision：
       deny 或部分动作 deny → AuthorizationDenied 403
       handle/OBO/传输/超时/非法响应 → AuthorizationUnavailable 503
    5. 全部 allow → 执行现有 export 查询并返回
  progress:
    1. 缺 Authorization → 401
    2. 其他情况 → 403 AuthorizationDenied (progress_surface_unbound)，无 Hub/DB/map 副作用
  retry:
    1. 缺 Authorization → 401
    2. 其他情况 → 403 AuthorizationDenied (retry_surface_unbound)，无 Hub/iTwinId/requeue 副作用
```

稳定响应（progress/retry，enforce）：

```json
{
  "code": "AuthorizationDenied",
  "reason": "progress_surface_unbound",
  "error": "Authorization denied: progress requires a server-session authorization context that this HTTP surface does not carry (AUTH_B3_SURFACES_MODE=enforce)"
}
```

- `reason` 只区分表面；消息不含 token/Authorization/handle/OBO/IP。
- export 错误沿用 `SessionError`：`AuthorizationDenied`（403）、`AuthorizationUnavailable`（503）。
- 不把 403 映射为 no-op 成功；不在 deny 后继续原有逻辑；不新增本地缓存 allow。

## 6. 明确残余表面（本切片未覆盖）

| 表面 | 当前状态 | 本切片 | 要求 |
|---|---|---|---|
| undo/redo/reverseTxns、`toggleGraphicalEditingScope` | owner-gated，无 doc ACL | **不覆盖** | 由 read-purity/undo 切片拥有；B3 关闭前必须分类 |
| `closeIModel` | session registry owner；关闭可能保存 pending 改动 | **不覆盖** | 同上；不得宣称 close 已受 ACL |
| assembly helpers（`createAssembly`/`listAssemblies`） | session/ownership only；进程内 `_findDb` | **不覆盖** | 需独立切片 |
| saved views / camera paths 四个 RPC | session path/ownership only | **不覆盖** | 需独立切片 |
| `/ws` progress 推送 | 按订阅/session 路由，无 doc.read 决策 | **不覆盖** | 设计 §5.4 要求授权推送；未实现 |
| tile / storage / SAS / nginx `/azurite` | 匿名或 bearer SAS | **不覆盖** | B3.1f 后续项 |
| WA `/baseline/process`、`/webhook/events` | 共享 key / HMAC | **不覆盖** | X-21 |
| Hub 命名版本/checkpoint 数据面 | legacy/flag | **不覆盖** | X-17/X-21 |
| export over HTTP RPC | `HTTP_STATEFUL_RPC_MODE=deny` 默认阻断；`allow` 时无 session→403 | 仅 fail-closed | 不依赖 HTTP 导出 |
| export 的审计/HITL、每 session briefcase 所有权 | 无 | **不覆盖** | P0-10 产品决策；当前仅 per-user ACL + 活跃 session |
| BFF 的逐路由授权/路径 allowlist | 无（通用 `/api` 代理） | **不覆盖** | 见 §9 决策 2 |

`pepCoverage` v5 对这些项保持 `p0-not-covered`，并在 note 中写明“excluded from B3.1f-a
(residual)”；`uncoveredEntries()` 仍把它们计入未覆盖，测试显式断言。

| R1 | **progress/retry 无法在不做产品/传输决策的情况下绑定用户 ACL**：两路由只有 bearer，无 session/OBO handle；progress 无 iTwinId，retry 的 iTwinId 来自 body。本切片只能 fail-closed | **待决**：①每请求从 bearer 签发 delegation handle→OBO→decision（需 iTwinId 解析、Hub 限流/延迟/配额、handle 生命周期）；②要求 `/ipc` session（路由/前端传输改造）；③把 progress/retry 迁到 Hub 用户路由由 Hub PEP 判定。三者都不得以“猜 userId 对应的 WS session”实现 |
| R2 | **retry 仍以服务账号 + 共享 key 调用 HUB requeue**（`off` 路径）；即使未来绑定 ACL，`requestedBy=user` 归因与 Hub 用户 retry 路由也未实现 | X-21/B6/B3.1e 前不得宣称用户归因；本切片 enforce 下直接 403，不触达服务凭据 |
| R3 | **单一开关耦合**：`enforce` 同时关闭 progress/retry，可能打断运维/未来前端调用 | canary 明确预期；如 owner 要求分离开关，需另立 AIRR（本切片按审计要求使用单一 `AUTH_B3_SURFACES_MODE`） |
| R4 | **export 的 ACL 是 per-user，不是 per-session**：同用户的另一个活跃 /ipc session 仍可导出进程内已打开且其有 `doc.read` 的 db；export 复用同 session/iModel 的 `doc.read` 决策缓存（≤30s，与 FeatureOp 读共享 scope），撤销窗口内可能仍 allow | 本切片要求活跃 session + 服务端 db iTwinId；每 session briefcase 所有权/审计/HITL/更短缓存留待 P0-10 产品决策 |
| R5 | **export 在无 db/standalone/snapshot 时 403**：legacy 可能对未打开 db 返回“not found”包装错误 | 预期 fail-closed；canary/前端流程需确认；不放松 |
| R6 | **BFF 没有路径 allowlist**：`/api` 仍是通用 JWT 终止代理；本切片只保证 401/403 原样、无重试 | **待决**：是否把 BFF 收敛为显式 `/api` 路径 allowlist（哪些 MS 路由由 BFF 拥有）。这是产品/传输决策；当前以 `BFF_PEP_COVERAGE` 显式登记 + 拒绝保留测试为准，不擅自限制现有 `/api` 面 |
| R7 | **未跑真栈**：export 的真实 Hub allow/deny、progress/retry 403、BFF 透传、无副作用均只有 unit/fake Hub 证据 | 隔离 Hub+MS+BFF canary 后再宣称；未跑即 unproven |
| R8 | **读强制的既有残余**：handle 15m/16 uses、决策缓存 ≤30s、撤销窗口、无 native 组合；export 与其他 `doc.read` 读共享该缓存 | 继承 B3.1c 风险；不得因 surfaces=enforce 宣称读链路完整或导出撤销即时生效 |
| R9 | **残余表面（undo/close/assembly/saved views/WS progress push/tile/storage/WA）** | 本切片明确不覆盖；B3 关闭前必须逐项分类或登记例外 |
| R10 | **X-27 未关闭**：BFF 仍无逐路由 PEP；Hub/BFF/WA/storage 仍 legacy | 本切片只更新 manifest 注记与状态，不改例外登记；由集成批次统一更新 |

**需要 owner 决策的最小集合**

1. progress/retry 的 ACL 传输方案（R1 的三个选项）与时间窗；在此之前保持 `AUTH_B3_SURFACES_MODE=off`。
2. BFF 是否引入显式 `/api` 路径 allowlist（R6）；若引入，需列出所有合法 MS `/api` 面。
3. export 是否需要审计/HITL 以及每 session briefcase 所有权（R4/R5）。
4. canary 范围：Hub+MS+BFF 隔离栈，至少覆盖 admin allow、View/outsider deny、progress/retry 403、
   BFF 403/401 原样、Hub 日志无 token/key/secret。

## 10. 评审结论

- 复用矩阵：完成（单一 OBO/decision 传输；export 复用读 gate；无第二策略引擎；不改 Hub）。
- 跨仓影响：仅 MS + BFF manifest/测试 + 公共文档；Hub/shared/web/editor/WA/worker 未改。
- 开关/回滚：默认 `off`；`enforce` 组合启动校验；回滚无迁移；off 路径零新增调用（现有测试通过）。
- 证据诚实：MS 新增/定向 77 测试通过、全量 172 files/1764；BFF 3 files/37；tsc 双侧通过；
  **无真栈 canary**，progress/retry 的 ACL 绑定仍为**待决阻塞**，不得宣称 B3.1f-a 已生产可用。
- 结论：**实现完成、默认 off，待 owner 决策与隔离 canary**；B3/X-21/X-27 保持 open；不勾 G1 Gate。
