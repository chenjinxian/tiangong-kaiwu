## 4. 逐项执行卡

### S-G2-01 Manifest 生成 dry-run

**问题**：能否用一份机器可读 Manifest 覆盖现有 21 个 `LubanFeatureType`，生成/校验
TS 类型、zod、registry 元数据、opDsl 白名单、formSchema、ribbon/capability 与 AI spec，
并证明生成结果与当前手写面**零意外差异**？

**环境**
- 公仓只读 checkout；`packages/shared` 可编译。
- 临时目录放 manifest fixture 与生成结果；**不合并、不提交、不改产品路径**。
- 不需要 Hub/MS/DB；如需要后端 registry 对照，只读消费私有产物，不写库。

**输入**
- `LubanFeatureType` 21 类型源码（`packages/shared/src/rpc/LubanFeatureRpcInterface.ts`）。
- `opDsl.FEATURE_TYPES` 当前 20 项（`packages/shared/src/opDsl.ts`）。
- `FeatureParams`/各 Params 类型、`FeatureFormFieldKind`、公开 ribbon/capabilities 面。

**步骤**
1. 从源码盘点 21 类型与 20 项 opDsl，记录差集（预期 `draft`）。
2. 写临时 manifest fixture：每个类型至少含 `type/paramVersion/paramsSchema/
   formSchema/inputs/outputs/structuralKeys/evaluatorKey/capability/i18nKey`；
   未知/不可表达的字段显式登记，不得省略后假装覆盖。
3. 跑生成器 dry-run，输出到临时目录：TS union、zod、registry 元数据、opDsl 白名单、
   formSchema、ribbon/capability、AI spec、测试清单。
4. 对生成物做 diff：与现有手写面逐项比较；记录“必须保留的例外”和“应删除的手写源”。
5. 用 `strict:true` 对临时生成物做 `tsc --noEmit`；跑 DSL 往返（21/21，含 `draft`）。
6. 反向检查：新增一个假的第 22 类型，确认只改 manifest 即产生类型/opDsl/form/capability，
   不触碰 9+ 手写点；改回，确认无残留。
7. 检查 `paramVersion`：旧 params 缺省=legacy 1；未知高版本=拒绝；新写带版本。
8. 记录生成时间、hash、diff 行数、失败项；不写入产品仓库。

**通过判据**
- 21/21 类型有 manifest 条目；opDsl 21/21；`draft` 可解析；21/21 DSL 往返。
- 生成物在 strict 下编译；生成 diff 中不存在“必须手改才一致”的项。
- 新增假类型只改 manifest（+ evaluator 占位）即可产生全部契约面；删除后零残留。
- `paramVersion` 缺省/未知/新写三种路径行为符合 ADR-G2-01。
- 现有手写面可作为生成物的**消费者或临时 adapter**，不再是第二事实源。

**失败判据/失败动作**
- 任一类型无法表达（如结构键/多输出/端口）→ 该类型标记 `manifest-not-ready`，
  **不得新增该类型或依赖它的功能**；修 manifest schema 或缩小首批覆盖，不伪造 21/21。
- 生成器需要手改生成物才编译 → FAIL；改生成器/模板，不把生成物变成手写。
- strict 编译失败或 opDsl 仍漏类型 → FAIL；停止 Manifest 冻结，先修契约/类型。
- 只能覆盖“简单类型”而复杂类型靠特例 → FAIL；把特例登记为例外并阻塞 G4，不得宣称
  “新特征 ≤3 注册点”。

**证据**
- 公开：命令、生成 diff 摘要、21/21 表、strict 编译结果、DSL 往返日志（脱敏）。
- 私有：后端 registry/zod 对照（如有）只放私有受控目录。

**不证明什么**：不证明 UI 已消费 formSchema、不证明后端求值器已迁移、不证明 DAG/多输出。

### S-G2-02 Split/Mirror 两端口下游消费

**问题**：一个特征声明两个输出端口（split 保留侧/移除侧，或 mirror 新体/源体）后，
下游特征能否按 `{featureId, portId}` 正确消费，而不是只能读“唯一源缓存”？

**环境**
- 隔离栈（真实 MS + 隔离 Hub/Azurite/Postgres）优先；至少 StandaloneDb + 真实 evaluator
  的可复现路径。
- 合成 Part Studio：一个 box/cylinder 作为源体；split 或 mirror 特征；下游 fillet/pattern。
- 不使用生产数据；所有写操作在可丢弃 iModel/briefcase。

**步骤**
1. 建立单源体，执行 split 得到两输出（保留/移除）或 mirror 得到新体；为输出分配稳定
   `portId`（如 `main`/`tool`/`newBody`）。
2. 验证输出表：每个 body 恰一个 active 生产者输出；特征有两个 outputs；无 body 双写。
3. 下游 fillet/pattern 显式引用 `{featureId, portId}`；分别消费两个端口。
4. 在 split/mirror 之前插入一个改变拓扑的特征；再删除中间特征（若执行器暂不支持，
   记录为预期失败，不得绕过）。
5. 保存/冷重开/重建；比较树、输出端口、body 归属、体积/包围盒。
6. 反向：删除一个端口/把两端口指向同一 body，确认拒收而非静默覆盖。
7. 记录是否仍存在“多目标输出缓存终态不能被下游消费”的限制（当前审计事实）。

**通过判据**
- 两端口均可被下游消费；下游结果几何正确（体积/bbox/拓扑符合预期）。
- 一 body 一生产者输出；端口键唯一；无 `multiBodyOutputCache` 终态限制。
- 冷重开后端口/下游引用仍正确；插入/删除要么正确重算，要么 fail-closed 且给出诊断。
- 旧单输出特征不受影响（零回归）。

**失败判据/失败动作**
- 下游只能读一个输出，或第二端口被拒绝 → FAIL；只冻结 C2 信封，**不冻结执行器**；
  停止新增多输出特征（split/mirror/pattern 多 body），继续用单输出语义。
- 端口解析到错误 body/静默复用旧缓存 → FAIL；回退到单输出路径，修 evaluator 输入边，
  重新 spike。
- 需要重写 FeatureRow 持久布局才能通过 → 记录为超范围；G2 不冻结持久布局，交由
  后续图执行器 ADR。
- 插入/删除测试无法执行（当前执行器限制）→ 标记 `BLOCKED`，不得写成 PASS；输出契约
  可保留，但多输出功能不得铺开。

**证据**
- 公开：输出表、树、端口键、体积/bbox、冷重开日志（脱敏）。
- 私有：真实 evaluator/内核日志只放私有受控目录。

**不证明什么**：不证明完整 DAG、不证明任意插入/删除/回滚、不证明装配多实例。

### S-G2-03 Typed Tab 双读兼容

**问题**：在不迁移旧文档、不删除 `UserLabel` 前缀的前提下，`listTabs` 能否把旧
Part Studio scope 合成为 typed `partStudio` tab，并让旧 URL/旧前端零回归？

**环境**
- 隔离 iModel/StandaloneDb，含：多个旧 `LubanFeaturePartition:<id>` scope、一个
  degraded scope（缺 phys model）、一个空文档。
- 临时只读 adapter/harness 模拟 `listTabs` 与 `listPartStudios`；**不写产品代码**。
- Web dev 或最小路由测试；不需要部署形态。

**步骤**
1. 盘点旧文档的 scope 标签、id/order/name、def/phys model、degraded 状态。
2. 在临时 harness 中实现 `listTabs` 双读：legacy 标签 → `{tabType:"partStudio", id,
   name, order, modelSet}`；degraded 保持可见并标记；未知前缀不猜类型。
3. 对照 `listPartStudios`：id/order/name/损坏状态必须一致；`listTabs` 是超集，
   `listPartStudios` 是过滤视图。
4. 打开旧 URL（无 `?model=`/无 kind）：默认 partStudio/第一个完整 scope；打开指定
   `?model=`：命中同一 scope；缺失/损坏 scope 的处理与旧行为一致。
5. 增加一个“stub assembly tab”只读条目（不实现功能）：确认 Part Studio 路由/树/选择/
   相机零改动；未知 kind 的打开请求 fail-closed。
6. 检查状态键：feature 树/body/对话框/相机/undo 的 key 是否含 document+workspace；
   切 scope 失败时旧树/旧 body 是否清空（当前已知缺口）。
7. 确认旧标签未被删除、未回写、未全量迁移；新 tab 写入路径不存在或默认 off。

**通过判据**
- 旧文档全部 Part Studio 被合成，id/order/name 与 `listPartStudios` 一致；degraded 可见。
- 旧 URL 默认/指定 scope 行为与旧版一致；无 404/重定向回归。
- stub tab 不改变 Part Studio 任何模块；未知 kind fail-closed。
- 旧文档零迁移、零标签删除；`listPartStudios` 仍可用。
- scope/state 键隔离；“切 scope 后旧树残留”不再出现。

**失败判据/失败动作**
- 旧 scope 漏列/顺序漂移/degraded 消失 → FAIL；保留旧 `listPartStudios` 为唯一读面，
  不冻结 typed tab。
- 旧 URL 打开错误 scope 或要求迁移 → FAIL；修合成规则/默认值；不得用迁移掩盖。
- 新 tab 类型导致 Part Studio 路由/状态分叉 → FAIL；回到 stub 编译验证，不实现工作区。
- 必须删除 UserLabel 才能双读 → FAIL；说明 `UserLabel` 是隐式契约，先补兼容再谈冻结。

**证据**
- 公开：旧 fixture manifest/hash、`listTabs`/`listPartStudios` 对照、URL 测试、stub 编译。
- 私有：含客户数据的 `.bim` 只放私有受控目录，公开只放脱敏结论。

**不证明什么**：不证明 Assembly/Drawing 功能、不证明版本打开/版本引用、不证明 WorkspaceModule
完整生命周期。

### S-G2-04 拓扑/选择引用稳健性与批量 Pick

**问题**：在有两个同构 body、插入/删除改变拓扑、顶点无持久 id 的情况下，
`TopologyRef`/`SelectionRef` 是否能避免“静默命中错误边/面”，并为批量选择提供可用预算？

**环境**
- 隔离栈：真实 MS + 隔离 Hub/Azurite/Postgres；可丢弃 iModel。
- 合成多 body 文档：两个相同 box/cylinder（同 node/entity 序列），一个改变拓扑的中间特征。
- 500 面模型用于批量 pick 预算；记录 IPC 次数与 p50/p95。

**步骤**
1. **基线复现**：分别拾取 body A/B 的边/面；记录裸 `{nodeId,entityId}` 是否相同；
   用旧路径提交 fillet/面操作，观察是否可能命中另一 body。
2. **限定引用**：构造 `TopologyRef {documentRef,workspaceRef,bodyKey,persistentId}` 与
   `SelectionRef`；重复步骤 1，确认 body/workspace 进入引用且解析不跨 body。
3. **插入/删除**：在引用上游插入/删除特征改变拓扑；解析旧引用，记录“正确命中 /
   fail-closed / 静默错命中”三态；不得把“找不到”当成功。
4. **顶点**：拾取顶点并持久化；若当前无持久 id，验证返回“显式 unsupported/需重新拾取”，
   不得用坐标巧合当身份。
5. **选择域**：同一选择在 store/SelectionSet/树/工具内部四套表示间投影；确认只有
   `SelectionDomain` 一个权威，旧 `CanvasSelection` 仅是投影。
6. **批量 pick**：500 面模型 hover/框选/拓扑快照；记录 IPC 次数、p50/p95、FPS；
   对照逐面 RPC 基线；验证 `geometryGuid/revision` 缓存失效。
7. **格式标签（可选子步）**：对同一 body 的 `BRepData` 读取，记录是否有
   `format/kernel`；无标签按 legacy ACIS 解释，未知标签拒绝。完整兼容见 S-G2-06。

**通过判据**
- 新 `TopologyRef`/`SelectionRef` 必带 body/workspace；跨 body 永不静默命中。
- 插入/删除后：要么正确解析同一拓扑实体，要么 fail-closed 且可诊断；无“status=1 但
  改了另一条边/面”。
- 顶点：有持久 id 或显式 unsupported；不得伪持久化。
- 选择只有一个权威；四套表示不再各写状态。
- 批量 pick：500 面在预算内、单次/少量 IPC、无逐面风暴；缓存键含 revision；旧逐面
  路径仍可用（默认 off）。
- 旧单 body 文档零回归。

**失败判据/失败动作**
- 交叉 body 静默错命中 → **STOP**；只允许 body/workspace 强制限定；多 body/多输出功能
  停止；不得用几何回退掩盖。
- 插入/删除后无法区分“同一拓扑”与“复用 id” → FAIL；引用需要持久 id/版本或显式失效；
  阻断历史编辑。
- 顶点只能靠坐标 → 标记 unsupported，禁止装配/约束依赖顶点身份；不得写“已支持”。
- 批量 pick 超预算 → FAIL；先冻结只读 DTO，实现后置；不得宣称大模型/装配可用。
- 选择仍多权威 → FAIL；先修选择域，不冻结 `SelectionRef`。

**证据**
- 公开：bodyKey/nodeId/entityId 日志、解析结果三态表、体积/bbox、pick IPC/p50/p95、
  revision 缓存记录（脱敏）。
- 私有：真实内核/几何日志只放私有受控目录。

**不证明什么**：不证明装配 occurrence、不证明 GPU pick、不证明 tile face/edge ID 已完成。

### S-G2-05 Session/Command/Undo 所有权 Shadow

**问题**：两个独立 session 上下文（同一文档或不同文档）能否各自拥有 store、连接/RPC token、
命令注册与 undo 所有权，而不串状态、不出现两套用户可见 undo？

**环境**
- **硬前置**：G1 C1/C2/C3 会话隔离 + S0-1 双用户证据已成立；否则本 Spike 只能作为
  contract/shadow，**不得替代 G1 证据**。
- 隔离栈 + 两个独立浏览器上下文；一个只读、一个编辑；可丢弃 iModel。
- 临时 shadow harness/feature flag；不进入产品默认路径。

**步骤**
1. 建立两个 session key（含 document + session/user）；各自创建 store 实例、连接、
   显式 RPC token；确认无模块单例/全局 fallback token 串用。
2. 注册一个 dummy command：定义 id/label/i18n/icon/group/keymap/capability/toolSpec/
   handler；验证 ribbon、palette、keymap、capability、AI spec 五处同源出现。
3. 删除/禁用该命令：五处同时消失；旧 if/else 路径仍可工作（adapter）。
4. 两个 session 各提交一个操作组（可用 shadow op）；验证 undo 只撤销本 session 的组；
   pull 后跳过他人组；最新组不可逆时停止而非跳过。
5. 验证用户可见 undo 栈只有一套；FeatureOp/直改/草图组顺序一致；预览/取消/失败不产生组。
6. 关闭一个 session：另一个不受影响；旧页面路由/单例 adapter 零回归。
7. 记录 G1 双用户/S0-1 证据和 UD-01..UD-10 状态；未通过项不得写成 shadow 通过。

**通过判据**

### S-G2-06 BRepData Format/Kernel 标签兼容

**问题**：给 `BRepData` 增加 additive `format/kernel` 标签后，旧无标签几何仍可按
legacy ACIS 读取/重建；未知/混合标签不会被静默当 ACIS 吗？

**环境**
- 隔离栈 + 旧 iModel fixture（无标签几何流）。
- 只读 native/geometry stream 代码；不接 TrueForm、不改几何字节。
- 若需要 native 构建，按 P0-08 单一 canonical/provenance 规则执行。

**步骤**
1. 读取旧 fixture 的 geometry stream，记录当前只有 `brepType`、无 `format/kernel`。
2. 在临时/隔离路径加 additive 标签（不批量改写旧数据），验证旧读取路径可忽略标签；
   新读取路径报告 `legacy/absent` 或 `ACIS`。
3. 读取旧 fixture：打开/重建/几何/体积/bbox 与加标签前一致；无新增写事务。
4. 制造未知标签、混合标签、后端不支持组合；确认写入/重建 fail-closed，错误可诊断。
5. 写入一个新标签的 ACIS 几何并读回；确认标签随几何持久化，不进入 `params`。
6. 回滚：关闭标签消费，旧读取路径仍能读 ACIS；不删除标签/不重写历史。

**通过判据**
- 旧无标签 fixture：可读/可重建/体积一致；状态报告 legacy/absent。
- 新标签写入/读回可诊断；未知/混合/不支持组合拒绝，不静默按 ACIS 解释。
- 标签 additive，旧代码可忽略；不进入 `params`；不改写旧几何。
- 回滚后旧路径仍可用；无 schema/native 破坏性变更。

**失败判据/失败动作**
- 旧 fixture 加标签后不可读/几何变化 → **STOP**；不得进入任何 TrueForm/双格式工作；
  保持 ACIS 无标签现状并登记阻塞。
- 未知标签被静默按 ACIS 读 → FAIL；改为 fail-closed；不得发布。
- 标签必须改旧字节/批量迁移 → FAIL；G2 不冻结该标签形态，重新设计 additive 方案。
- native/provenance 不可复现 → FAIL；不得把本地 dev build 当证据。

**证据**
- 公开：旧 fixture manifest/hash、读取/重建结果、体积/bbox、未知标签负例（脱敏）。
- 私有：native 构建/provenance 证据只放私有受控目录。

**不证明什么**：不证明 TrueForm 可用、不证明 SAB 迁移、不证明双后端一致性。
