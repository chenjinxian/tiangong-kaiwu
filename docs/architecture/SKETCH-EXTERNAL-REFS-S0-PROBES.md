## 逻辑操作与证据

### 1) SILHOUETTED（轮廓）

- 检索：`SolidKernel.h`、PSBRep 操作层、编辑 IPC/TS 工具——**无**轮廓/outline API。
- 基础体轮廓接口存在，但对盒/拉伸/旋转扫掠/直纹扫掠返回 false；锥/球为精确线/弧；环的一般情形输出折线（采样），不可用于“精确”要求。
- 几何内核 SDK 存在面级精确轮廓接口（内部头，平行/透视投影，按面边界裁剪）。
- 临时测试证：圆柱侧面沿一轴向视向 → 2 条精确直线；球面沿一轴向视向 → 1 个精确圆（椭圆比 1）；端盖 0 条。
- **未证明/阻断**：ALIGNED/ANTI_ALIGNED/OUTER/INNER 与草图法向/视向的语义；面/体范围与多段环装配；该接口属内核内部 API，授权范围（P0-09）需评审。**无产品链路**。

### 2) 面 × 草图平面（INTERSECTED）

- 既有暴露面：面-面求交（返回曲线）、由面建片体、平面面转曲线；均无 JS/TS 线（编辑 IPC 只有实体布尔/切除等，输出实体而非曲线）。
- 既有暴露面探针（临时原生测试）：
  - 盒体实体 × 平面 → 4 条精确直线；盒体面片 × 平面 → 1 条精确直线；斜切盒体 → 2 条精确直线；球体 × 平面 → 精确圆。
  - **圆柱/圆锥/环体/拉伸圆柱 × 平面 → 失败、0 曲线**（即使平面完全覆盖截面）。
- 由面建片体已有回归证据：圆柱体的全部 3 个面（含平面端盖）在创建器处按契约拒绝，因此“先取面片再求交”的绕行不通。
- 内核 SDK 精确平面切片接口存在（官方文档：返回可用于一般用途的线体，表示体×平面交线）。临时原始内核测试证明：
  - 圆柱 × 水平面 → 1 个精确圆（椭圆比 1）；
  - 圆柱 × 斜面 → 2 段精确椭圆弧 + 2 条直线；
  - 圆柱 × 轴向平面 → 4 条精确直线；
  - 盒体 → 精确直线。
  - 注意：返回线体带自身变换，包装层必须合成到世界坐标。
- **结论**：精确算法**存在且被证明**，但当前**未暴露**；产品要落地需新增内核包装 API + JS 线 + native 接口 ADR + ctest。非圆椭圆弧不在现有草图 arc DTO（圆心/半径/角度）能力内，须拒收或另立 DTO 扩展契约；不得采样/折线化。

### 3) 边 × 平面（PIERCE）

使用 `@itwin/core-geometry` 的 `CurvePrimitive.appendPlaneIntersectionPoints`（临时 Node 探针）：

| 输入 | 平面 | 结果 | 备注 |
|---|---|---|---|
| 直线穿越 | 一般位置 | 1 点 | 精确 |
| 直线平行 | — | 0 | — |
| 直线在平面内 | — | **0** | `isInPlane()` 为 true；必须单独识别 |
| 整圆 | 过直径 | 2 点 | 精确 |
| 1/4 圆弧 | 过起点 | **2 点** | 第 2 点在弧扫掠外（fraction=3）；必须按 [0,1] 过滤 |
| 半圆弧 | 切割 | 2 点 | 其一 fraction=1.6667（弧外） |
| 圆 | 相切 | **1 点** | 切点与普通单点不可区分 |
| 圆在平面内 | — | **0** | 必须失败封闭 |
| 椭圆 | 过中心 | 2 点 | 精确 |
| 三次样条（单/多简单根） | — | 1/3/5 点 | 代数精确 |
| 对称三次样条（三重根） | — | **0** | 重根漏解 |
| 2 阶样条 | — | 计数与明细不一致 | 调用方需以明细数组为准并去重 |

- **可用于 PIERCE**：line/arc 解析精确；spline 简单根数值精确。
- **失败封闭要求**：线/弧在平面内；弧切点；弧结果超出扫掠；spline 重根/在平面内/计数不一致。首版对切点与多义形态按 AIRR 失败封闭。

### 4) libslvs 固定参考几何

现状：solver-neutral 的 `fixed` 只接受单点，参数进入锁定组、不占 DOF；`coincident` 支持点-点/点-线/点-圆/点-弧，**不接受点-样条**。临时 vitest 探针（已删除）：

| 场景 | DOF | 结果 |
|---|---:|---|
| 自由线 + 点在线上 | 3 | 点落线 |
| 线两端点 fixed + 点在线上 | **1** | 线固定且零 DOF，点沿线滑动（可约束） |
| 隐藏 fixed 点 + coincident 本地点 | **0** | 点精确落到固定点 → PIERCE 展开可表达 |
| 圆心 fixed + 半径约束 + 点在圆上 | **1** | 圆净零 DOF，点可约束 |
| 弧仅 fixed 圆心 + 半径 | **2** | 弧几何仍可变（隐藏起/终点未锁） |
| 弧 + 两个隐藏 fixed 端点 + coincident 到弧端点 | **0** | 弧完全固定，点可约束 |
| 样条四控制点 fixed | 2（仅自由点） | 样条净零 DOF；点-样条 coincident 校验拒绝 |

- **结论**：line（两端点 fixed）、circle（圆心 fixed + 半径）、arc（圆心 + 半径 + 两个隐藏 fixed 端点 + coincident）、spline（四个控制点 fixed）均可用**内部合成约束**表达“固定参考曲线”，无需先改 solver-neutral 契约；隐藏点会出现在解点表中，后端须过滤（既有 origin 归一化同款做法）。
- **PIERCE**：隐藏固定点 + coincident 已可直接表达。
- AIRR 的实体级 `fixed` 是便利性/健壮性增强，非 line/circle/arc/spline 的硬前提；若采用仍需 solver-neutral ADR（P0-09）。
- **唯一硬契约缺口**：point-on-spline 被拒收；样条边 PIERCE 需要 solver-neutral 约束扩展（ADR）或按 AIRR 拒收，不得折线近似。

## S1/S2/S3/S4 门禁建议

- **S1 边/顶点投影**：不因 S0 阻塞；按 AIRR 继续（spline 边拒收）。
- **S2 PIERCE**：line/arc 可做；落实探针 3 的失败封闭规则；隐藏固定点方案可行。样条边 PIERCE 保持 blocked。
- **S3 平面面边界**：可用现有面环读取；但不得假设任意平面面都能由面建片体（圆柱端盖被拒），须逐面验证环可精确转换，否则整面拒收。
- **S4a INTERSECTED**：**条件性可行**——需先完成内核精确切面 wrapper + JS 线 + native 接口 ADR + ctest；输出限 line/圆/圆弧（非圆椭圆拒收或另立 DTO 扩展）。禁止用现有面-面求交 API 处理曲面（已证失败）。
- **S4b SILHOUETTED**：**blocked-design/kernel**——精确内核内部接口存在且技术可行，但未暴露、授权范围待评审、live 语义未证；需 native ADR + license 确认 + 语义证据后才可开工。禁止近似。
