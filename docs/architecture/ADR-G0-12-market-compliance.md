# ADR-G0-12：目标市场、数据驻留、出口与许可 stop-ship

> 状态：**Proposed under owner directive 2026-11-24; not ARB-signed**（业主指令下拟制，尚未经 ARB 签字）
> 日期：2026-11-24
> 关联：`G0-DECISION-REGISTER.md`（D0-12 目标市场/合规）、`G0-EXECUTION-PLAN.md` §4/§6、`09-INDUSTRIAL-TARGET-ARCHITECTURE.md` §5.5/§12/§13、`10-ARCHITECTURE-HARDENING-PLAN.md` §0.5/WS-L、`ADR-G0-02`、`ADR-G0-07`（G0 计划项）、`ADR-G0-14`（G0 计划项）、`EXCEPTIONS.md` X-08/X-21/X-22/X-26
> 影响面：目标市场、数据驻留/跨境、客户数据准入、ACIS/libslvs/STEP 分发、SBOM/许可门、发布与销售口径
> 本 ADR 只冻结合规与许可门禁，**不选择**中国/全球/私有化市场，不提供法律结论；不含私有源码、密钥、私有路径或 native 构建证据。

---

## 1. 背景与当前事实

1. D0-12 的建议默认是：**先明确数据驻留/许可/出口，再决定收集客户数据；目标市场未定前不做生产数据托管**。失败判据是“未定驻留/许可就收集客户模型；公开分发未授权产物”。
2. 中国、全球、私有化是三种不同的部署/合规/分发姿态，涉及数据驻留、跨境传输、隐私、出口管制、ACIS 分发、GPL 义务、on-prem 打包与支持责任。该选择属于 **Product/Legal 裁决**，不是架构或工程可以默认决定的（09 §13、10 WS-L）。
3. 当前没有 Product/Legal 的书面市场/驻留/出口/分发决定；没有 DPA/隐私政策/子处理者清单/DSR（数据主体请求）流程；没有按区域/租户映射的存储、KMS、备份与日志。
4. 当前数据面仍是开发/单栈形态：Azurite 仅开发、无 PITR、无对象版本化/跨区、无恢复演练；G1 状态明确 **DR 未闭环、RPO/RTO 不能宣称**（G1 状态 §2 第 4 条）。G3 生产门未通过（10 §1/§5）。
5. 租户边界未建立：`tenantId` 为 nullable 占位、恒 NULL，无 RLS/跨租户负例（X-22）；B10 未做。审计仅 B7 v1：本地 PostgreSQL 触发器、无 WORM/异地不可变副本/保留期/legal hold，`tenantId=NULL`（X-26）。
6. 许可 stop-ship 现状（09 §13、10 §0.5）：
   - **ACIS**：仅 Modeler + Polyhedra；3D InterOp/STEP/IGES/healing 未授权、不得接线；对外分发含 ACIS 的产物需法务书面授权、第三方通知与出口分类。
   - **libslvs**：GPL-3.0-only；当前只允许纯云 SaaS 姿态；on-prem/客户端打包是红线；若公开 MS 产物包含 `slvs.node` 并对外分发，与现行政策直接冲突，发布前必须解决（X-08）。
   - **STEP/IGES/Parasolid**：无许可裁决前不接线、不承诺；mesh/DXF 先行的 D0-7 边界仍然有效。
   - **blocked-license 工具**（如 ThickenSheet）：必须在 native/服务入口 fail-closed，不得只靠 UI 隐藏。
7. 当前未获授权的能力若经 IPC/编辑器可达，即构成 stop-ship；09 §13 与 10 §0.5 要求在发布门而非 UI 层阻断。
8. 公开自助注册、分享 UI 在身份/ACL/租户/合规完成前不得开放（10 §0.5）；演示/试点环境同样可能承载客户模型，不能视为“非生产所以豁免”。

## 2. 决策

### D-A 市场与驻留由 Product/Legal 书面裁决

1. **本 ADR 不选择目标市场**。中国、全球、私有化（on-prem）均为候选；选择必须由 Product/Legal 出具**书面、签字、带日期与适用范围**的决定，明确：目标国家/地区、托管区域、跨境传输、数据驻留、子处理者、隐私/DPA、保留/删除、出口分类、许可/分发权、支持与事件响应。
2. **书面决定前不接收生产客户模型数据**。包括试点、试用、演示、设计伙伴与支持排障上传；只允许合成数据、内部测试数据与不含第三方机密的最小样例。
3. **决定必须落到可执行的区域/租户映射**：Tenant → 存储区域 → KMS 区域 → 备份区域 → 日志/审计区域 → 子处理者；任何客户数据不得出现在未批准区域。该映射由 ADR-G0-02 的租户模型承载。
4. 若决定选择中国/全球/私有化之一，必须新建或修订 ADR，重新评估部署形态、许可、出口、数据流与支持责任；不得以本 ADR 的“预留”代替市场决定。
5. **没有书面决定时的默认姿态是“不收集、不跨境、不分发”**；沉默不构成批准，口头/聊天/工单同意不构成书面决定。

### D-B 许可与分发 stop-ship

6. **ACIS**：只允许 Modeler + Polyhedra；3D InterOp/STEP/IGES/healing 不接线、不注册、不经 IPC 可达。对外分发含 ACIS 的镜像/产物前，必须有法务书面授权、第三方通知与出口分类结论。
7. **libslvs**：坚持 GPL-3.0-only 与“仅纯云 SaaS”姿态；禁止 on-prem/客户端交付打包。每个公开 MS 产物/镜像必须做二进制与 SBOM 审计；若包含 `slvs.node`，在合规方案（源码邀约/第三方通知/商业例外/移除）落地前不得对外分发（X-08）。
8. **STEP/IGES/Parasolid**：在许可/第三方翻译器/TrueForm IO 的书面裁决前，不实现、不承诺、不在 UI/API 暴露入口；mesh/DXF 能力按 D0-7 单独裁决。不得用近似 healing 或自研转换冒充精确交换。
9. **TrueForm**：其接入是独立 ADR/迁移门禁；不得以 TrueForm 作为规避 ACIS/STEP 许可或分发限制的依据；M1 前必须完成 SAB 兼容、双后端一致性、迁移与回滚（09 §9/§13）。
10. **blocked-license 工具**：在 native/服务入口 fail-closed；UI 隐藏不算控制。许可检查失败必须拒绝执行并记录，不得静默降级或返回假成功。
11. **发布门**：镜像/产物/SBOM/第三方通知/出口分类必须可对账；未通过许可门的产物不得进入 release manifest、公开仓库或客户环境。许可证清单与 SBOM 的证据由 ADR-G0-19（G0 计划项）承接。

### D-C 客户数据准入与保护

12. **生产客户数据的最低门槛**：G3 生产控制（TLS、KMS/静态加密、Postgres HA/PITR、对象存储版本化/跨区、DR 演练、审计保留）＋ ADR-G0-02 的租户隔离 ＋ ADR-G0-16 的真实归因 ＋ 本 ADR 的书面市场/驻留决定。缺一不得接收生产客户模型。
13. **身份/ACL/租户前置**：公开自助注册、邀请、链接分享在 B3/B4/B10 与合规控制完成前保持关闭或标记 blocked；per-doc ACL 与租户边界是外部用户准入的前提。
14. **日志/遥测**：不得记录客户模型内容；PII 最小化、脱敏、保留期与访问控制必须定义；token/密钥不得进入日志。日志/审计/备份的存储区域必须与书面决定一致。
15. **数据主体请求与删除**：上线前必须有 DSR（访问/导出/删除/更正）流程、保留期、legal hold 边界与租户删除/残留检查；删除必须覆盖 DB、对象存储、tile、备份与日志。
16. **合规声明**：可以建设 SOC 2/ISO 27001 类控制，但在独立审计/认证完成前不得宣称“已认证/合规”；09 §13 明确认证是商务/审计结果，控制必须先存在。
17. **演示/支持/排障**：客户模型的任何上传（工单附件、演示环境、远程排障）都按生产数据处理；没有书面决定与最小权限/保留策略时不得收集。

## 3. 备选方案与拒绝理由

| 选项 | 内容 | 拒绝理由 |
|---|---|---|
| A | 先按中国市场建设并收集数据 | 市场选择未定；会把驻留/跨境/许可/分发假设写死，后续切换需迁移与重新合规 |
| B | 先按全球（默认单区域）建设 | 全球涉及跨境、隐私、子处理者与区域支持，未裁决前默认单区域可能造成不可逆传输 |
| C | 先做私有化/on-prem | libslvs GPL 与 ACIS 分发/出口未裁决；on-prem 打包当前是 stop-ship（X-08、09 §13） |
| D（本 ADR） | 先冻结 stop-ship 与数据准入；市场由 Product/Legal 书面决定；架构预留区域/租户映射 | 避免不可逆合规风险；不预设市场；与 D0-12 一致 |
| E | 先收试点客户数据，合规后补 | 数据一旦收集/跨境/进入备份，无法“回到未收集”；删除/泄露/审计风险不可逆 |
| F | 由工程默认选择市场/区域 | 市场/驻留/出口是法律与商务裁决，不是工程默认；会造成未经授权的数据流 |
| G | 直接分发含 GPL 二进制的产物，靠源码邀约兜底 | GPL 义务与 on-prem 姿态冲突；是否可接受需法务书面结论，不能默认 |
| H | 先接 STEP/IGES，许可后补 | 未授权接线本身违反 P0-09；对外承诺后无法撤回；许可/出口是发布门 |
| I | 用 TrueForm 绕过 ACIS/STEP 许可 | 内核切换不能替代格式/分发许可；TrueForm 自身需独立 ADR/迁移/许可评估 |
| J | 演示/试点环境不受生产数据门禁约束 | 客户模型在演示/试点中同样是第三方机密；环境隔离不等于合规豁免 |

## 4. 后果与风险

### 正向

- 在不可逆的数据收集/跨境/分发发生前设置门禁，降低合规、出口与许可事故。
- 许可 stop-ship 明确，避免 GPL/ACIS 二进制进入公开产物或客户环境。
- 市场决定与架构预留解耦：可以先建区域/租户/审计能力，不预设市场。

### 负向/成本

- 在书面决定前无法接真实客户试点/收入，短期商务压力大。
- 法务、隐私、许可、出口分类、SBOM、DPA/DSR 都需要专门投入与周期。
- 若选择 on-prem，可能需要重新设计分发/更新/支持；libslvs 与 ACIS 可能使 on-prem 短期不可行。
- 区域化部署/KMS/备份/日志会增加运维与成本。

### 主要风险

| 风险 | 触发 | 缓解 |
|---|---|---|
| 影子试点 | 销售/支持私自接收客户模型 | 数据准入书面门禁；环境审计；上传入口关闭/告警 |
| GPL 污染 | 镜像/MS 产物包含 `slvs.node` 或其它 GPL 二进制 | SBOM/二进制扫描；发布门；X-08 退出计划 |
| ACIS 未授权分发 | 公开镜像/安装包含 ACIS 组件 | 法务书面授权/第三方通知/出口分类；发布门阻断 |
| 出口/技术数据泄露 | 仓库/文档/支持包含受控技术数据 | 出口分类；仓库扫描；公开材料评审 |
| 区域漂移 | 备份/日志/子处理者落在未批准区域 | 区域映射 + 部署检查；DR 演练核对 |
| 删除不彻底 | 只删 DB 不删对象/tile/备份/日志 | DSR/租户删除演练；残留检查；保留期 |
| 合规虚标 | 未审计即宣称 SOC 2/ISO 或其它认证 | 发布/销售文案门禁；审计证据前只描述控制 |
| 许可工具旁路 | blocked 工具经 IPC/编辑器可达 | native/服务入口 fail-closed；入口清单与负例 |

## 5. 迁移、回滚与失败判据

### 迁移/准入流程

1. **数据分类**：区分合成/内部测试/客户模型/个人数据/受控技术数据；为每类定义允许环境、区域、保留期与访问者。
2. **书面决定**：Product/Legal 签署市场、区域、跨境、子处理者、出口分类、许可/分发与 DPA/隐私结论；记录日期与适用范围。
3. **区域/租户映射**：按 ADR-G0-02 的 Tenant 模型落地存储/KMS/备份/日志区域；部署检查拒绝未映射租户。
4. **许可/SBOM 门**：对每个产物做许可证清单、SBOM、二进制扫描、第三方通知与出口分类；未通过不得发布。
5. **数据保护控制**：TLS/KMS/HA/PITR/对象版本化/DR/审计/DSR/删除演练；G3 通过后才允许生产客户数据。
6. **对外声明**：能力账本/销售材料/UI 只描述已获授权与已验证的能力；ACIS/libslvs/STEP/on-prem 按 stop-ship 标注。

### 回滚

- 本 ADR 不涉及 schema/native 迁移；回滚对象是数据准入与分发决定。
- 若市场/驻留决定被撤销或变更：立即停止新数据收集，隔离/删除受影响数据，撤销访问与子处理者权限，按保留/legal hold 处理；**历史跨境传输不能回滚**，因此决定必须先于收集。
- 若许可裁决变化：停止分发/下架产物、撤回镜像、更新 SBOM/通知、通知客户；不得继续分发未授权二进制。
- 任何市场/许可变更必须新建 ADR 修订或新 ADR，不能直接修改本 ADR 结论。

### 失败判据

1. 书面决定前接收任何外部客户/第三方模型数据（含试点、试用、演示、支持附件）。
2. 对外分发含 ACIS 的产物而无书面授权/第三方通知/出口分类。
3. on-prem/客户端打包 libslvs，或公开 MS 产物含 `slvs.node` 而未解决合规方案。
4. STEP/IGES/Parasolid 在许可裁决前经 UI/API/IPC 可达或被对外承诺。
5. blocked-license 工具可通过 native/服务入口/IPC 执行。
6. 未完成 G3/租户/审计/DR 即接收生产客户数据，或宣称“数据可靠/可恢复”。
7. 未审计即宣称 SOC 2/ISO/合规认证，或公开材料含未授权许可声明。
8. 客户数据/备份/日志出现在未批准区域，或删除后仍有对象/备份/tile 残留。
9. 用“演示/试点/内部环境”规避数据准入或分发许可。

任一触发时：立即停止相关数据流/分发，升级 Product/Legal 与安全 owner，按事故/合规流程处理，并更新能力账本与例外。
