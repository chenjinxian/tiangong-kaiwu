# T1.4+T2.4 部署链统一 设计

日期：2026-09-27
状态：五节设计已获用户确认（编排=单根 compose 含 HUB；决策点 a=服务端双读 cookie；决策点 b=baseline 家族同钥）
上游：`docs/superpowers/specs/2026-09-26-platform-architecture-review-design.md`（T1.4+T2.4 合并实施）

## 目标

内网单机一条命令起全栈、一个域名入口；服务间残余无鉴权面清零（HUB baseline 家族）；WS 鉴权升级为同源 cookie（dev 直连回退保留）；验收命令化。

## 决策记录

1. **单根 compose 含 HUB**（build context `../imodelhub-services`；与 HUB 仓自有 compose 存在少量重复定义，以根 compose 为部署权威）。
2. **MS 容器化为最大技术风险点**：`link:` 指向 itwinjs-core 源码目录，容器内需复制源码+构建或预拷 lib 产物。实施先验证「构建产物进镜像」路线；失败回退 host network + 宿主进程（compose 以 `profiles: [host]` 保留该形态），记录裁决。
3. **WS cookie 双读（服务端）**：先 cookie 后 query；FE 零改动。
4. **baseline 家族同 guard 同钥**：`X-API-Key: AGENT_API_KEY`（HUB 新 env；与 WA/MS/脚本的 IMODELHUB_API_KEY 同值，compose 单源注入）。脚本无 key 时 fail-fast。

## 1. 根 docker-compose.yml

- services：`postgres`（17，HUB 最小配置）、`azurite`（10000，well-known key 由 env 注入）、`imodelhub`（build ../imodelhub-services；env 指向同 compose 的 PG/Azurite；迁移随其启动入口）、`webhook-agent`（build webhook-agent/；根 .env 值注入）、`modeling-server`（见决策 2）、`web`（build luban-cad/ FE 产物）、`nginx`（deploy/nginx.conf，:80 单入口）。
- 网络：单一 `stack` 网络；`volumes`：pgdata、azurite-data、briefcase-cache。
- 根 `.env` 为唯一注入源（既有）；compose 变量与 `.env.example` 对齐补齐缺口（AGENT_API_KEY=IMODELHUB_API_KEY 映射写注释）。
- `luban-cad/docker-compose.yml` 头注释改为「dev 参考，部署权威为根 compose」。

## 2. nginx 反代（deploy/nginx.conf）

- `/` → web:3000（静态产物服务）；`/api`、`/ws`、`/ipc` → modeling-server:4001（**Upgrade/Connection 头透传**）；HUB 前缀集 `/itwins /imodels /auth /accesscontrol /webhooks /users /files /oauth /.well-known` → imodelhub:4000；`/azurite` → azurite:10000（FE 直传）。
- 生产态 FE `VITE_API_URL` 留空 → 各 client 相对 URL 同源命中反代（现状已兼容）。
- WebSocket 超时（proxy_read_timeout）放宽至 3600s（长连接推送）。

## 3. WS cookie 双读

- `modeling-server/src/middleware/wsAuth.ts` verifyClient：解析 `req.headers.cookie` 中 `luban_cad_auth`（JSON，取 tokens.accessToken）作 Bearer；无 cookie 时回退现有 `?token=` query。两者都无→401。校验链（/auth/me 转发）不变。
- dev 直连（:3000→:4001 跨源）仍走 query（FE 钩子现状保留）；同源经反代自动携 cookie，query 从此不在反代日志出现（安全收益兑现）。
- 测试：cookie 路径（有效/无效/缺两处）+ query 回退路径各一。

## 4. HUB baseline 家族鉴权

- `imodelhub-services`：`iModelsBaselineController` 加 Nest Guard（或装饰器内联校验）：`X-API-Key === config AGENT_API_KEY`（env 缺失→启动即 fail-fast，防裸奔默认）。
- 脚本 `regenerate-baseline.ts` / `check-imodel-status.ts`：无 `IMODELHUB_API_KEY` env 时打印错误退出非零（替换 `|| ''` 降级）。
- compose 注入同一 key 值到 HUB（AGENT_API_KEY）与 WA/MS/脚本（IMODELHUB_API_KEY）。

## 5. 验收命令 scripts/verify-stack.ps1

- 前置：compose up -d 完成。
- 步骤：①各服务 health 探测（HUB /health、MS /health、WA 端口、web 200）②最小数据链路：服务账号登录→创建 iTwin→创建 iModel→轮询 baseline 状态到 initialized（超时 5min，失败给出 WA 日志指引）③WS 握手探测（cookie 模式，经 nginx）④MS 日志含 "using dev build"（原生库替换在位性——容器形态按决策 2 的实际路线校验）。
- 退出码汇总；输出通过/失败表。
- 文档：CLAUDE.md 启动顺序改「compose 优先，dev 分进程为开发态」；UPSTREAM_SYNC.md 附 compose 注意事项（itwinjs-core 重建后镜像需 rebuild）。

## 测试与验收

| 面 | 用例 |
|---|---|
| wsAuth | cookie 有效/无效/两处皆无/query 回退（4 案） |
| HUB guard | 无 key 401/错 key 401/对 key 200/启动缺 env 拒启 |
| 脚本 | 无 env 退出非零（1 案×2 脚本） |
| nginx | 路由表各前缀命中正确上游（配置 review + verify-stack 实测） |
| verify-stack | 全链路绿（生产门禁演示） |

**验收**：`docker compose up -d && scripts/verify-stack.ps1` 全绿；调用图与安全面无回归（MS/WA 套件全绿）。

## 边界与不做

- 不做多机/HA（单机内网拓扑）；不做 TLS（内网 http，反代留 443 占位注释）；DanQing/imodel-native 不涉及。
- MS 容器化失败时的 host 形态为已裁决回退而非失败。
- HUB 仓 compose 不删（其 CI 在用），仅根 compose 成为部署权威。
