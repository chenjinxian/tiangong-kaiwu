# T1.3 配置与密钥整治 设计

日期：2026-09-26
状态：设计已获用户确认（方案 A + 五节设计 + 三项决策：WS 鉴权推迟 T1.4 cookie、首启生成脚本、非密钥可默认/密钥必填）
上游：`docs/superpowers/specs/2026-09-26-platform-architecture-review-design.md`（T1.3 子项目）

## 目标

两服务（modeling-server / webhook-agent）的配置与密钥达到内网多用户交付底线：无硬编码密钥、无默认口令、缺配置拒启（fail-fast 且指名缺失项）、服务间认证强制、环境变量命名一套。

## 决策记录

1. **WS token 出 URL query 推迟到 T1.4**（反代同源后 cookie 自动携带；现在做首帧鉴权会在同源化后重做）。
2. **密钥来源 = 首启生成脚本**（非手工配置文档）。
3. **非密钥项（URL/端口/开关）保留 dev 默认值；密钥项一律必填无默认**。

## 1. 配置模块（每服务一个）

- `modeling-server/src/config.ts`、`webhook-agent/src/config.ts`：zod schema + 启动即 parse，导出 frozen typed config。
- 解析失败：打印全部缺失/非法项清单（变量名 + 期望），`process.exit(1)`。
- 全部 `process.env.*` 读取收敛至 config 模块（现状 30 个变量分散在 main.ts 及各文件）。

### 命名统一（破坏式）

`BLOB_{URL,CONTAINER_NAME,ACCOUNT_NAME,ACCOUNT_KEY}`、`AZURITE_URL`、`IMODELHUB_API_URL`、`BACKEND_URL` 全部弃用；统一为上表命名（`AZURITE_*`、`MODELING_SERVER_URL`）。`.env.example` 为唯一权威模板。

## 2. 强制认证（本仓闭环）

- MS：`/api/webhook/events`、`POST /api/imodels/:id/progress` 入站 API key 从「设了才验」→「必验，缺失/不符 401」；`/baseline/retry` 出站恒带 `WEBAGENT_API_KEY`。
- WA：入站 HMAC（`WEBHOOK_SECRET`）必验不变（已必验，仅 secret 无默认化）；`/baseline/process`（HUB 入站）在本仓侧无验证点（HUB 代码），记录 T2.4。
- WA→HUB 全部出站恒带 `X-API-Key: IMODELHUB_API_KEY`；HUB 是否强验归 T2.4。

## 3. 首启生成与模板

- `scripts/generate-env.ps1`：幂等（存在 `.env` 则跳过并提示）；用 `openssl rand`/`-join((1..32)|%{...})` 生成随机 hex：`BACKEND_API_KEY`、`WEBAGENT_API_KEY`、`CSRF_SECRET`、`WEBHOOK_SECRET`、`AZURITE_ACCOUNT_KEY`、`IMODELHUB_ADMIN_PASSWORD`、`IMODELHUB_API_KEY`；同时把两服务的 `.env` 写齐（或写仓库根单份 `.env`，两服务 dev 脚本读取——**采用仓库根单份 `.env`**，与 T1.4 compose 演进同构）。
- `.env.example` 入库（全部变量 + 注释）；`.env` 加入根 `.gitignore`。
- `IMODELHUB_ADMIN_EMAIL/PASSWORD` 是 HUB 的账号凭据：脚本生成密码后需在 HUB 侧完成注册/对齐——脚本输出提示（HUB 有 seed admin，见其 webhook-seed），不自动写 HUB 数据库。

## 4. 文档

- 根 CLAUDE.md「常用命令」补：首次运行 `powershell -File scripts/generate-env.ps1`；两服务 dev 前置要求 `.env`。

## 5. 测试策略（TDD）

- `config.test.ts`（两服务各一）：缺密钥 → 子进程运行 `tsx -e "import('./config')"` 退出码 1 且 stderr 含变量名；齐全 → 导出对象含默认值与生成值。
- 认证强制：MS security/userAuth 既有测试模式扩展——无 key/错 key 调 `/api/webhook/events`、progress POST 得 401；有效 key 通过。
- 回归：两服务全量 Vitest 绿（`projects/service.test` 存量失败除外）。

## 边界与不做

- 不动 WS token（T1.4）；不动 HUB 代码（T2.4 记录其对齐项）；不动 compose（T1.4）；不改 FE。
- `webhook-agent` 的 `.env` 旧变量如有外部脚本引用（start-all.sh 等）——检查并同步更新引用。
