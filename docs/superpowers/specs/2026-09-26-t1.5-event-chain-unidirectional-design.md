# T1.5 事件与进度链单向化 设计

日期：2026-09-26
状态：四节设计已逐节获用户确认（retry 路由=FE→MS→HUB；三轨方案 A/A/A）
上游：`docs/superpowers/specs/2026-09-26-platform-architecture-review-design.md`（T1.5 子项目）
前置：T1.2 契约统一、T2.1 webhook-agent 整治（均已交付）

## 目标

数据流单向化：消除 MS↔WA 双向 HTTP 环（retry 改 HUB 重新入队）；WA 转发达到至少一次投递（磁盘队列+重放+可观测）；`/ws` 推送激活，FE 进度轮询降级为兜底。

## 决策记录

1. **retry 路由 = FE→MS→HUB**（FE 调用面零改动；MS 留任认证代理；MS→WA 边消失）。
2. **至少一次投递 = 磁盘 JSON 队列**（复用 T2.1 store 模式；不上 SQLite）。放弃条目以指数退避无限重试而非丢弃。
3. **/ws 激活 = MS 广播 + FE 订阅钩子 + 轮询保留为降级兜底**（不删除轮询）。

## 1. 拆环：HUB requeue + 三方改造

### HUB（imodelhub-services）
- 新 `POST /imodels/:id/baselinefile/requeue`（agent-facing 控制器，与 `/failed` 同族，注释标注本地扩展）。
- 行为：iModel 存在校验 → 当前 `state===initialized` 则 **409**（已成功不可重入队）→ 否则状态翻回 `notInitialized` + `setOperationWaitingForFile` → 返回 `{iModelId, state}`。
- 依据：`GET /imodels/admin/uninitialized` 收录 `['notInitialized','failed']`（imodels-admin.controller.ts:54），翻回即入列，WA 5 分钟恢复轮询自然拾取。

### MS（modeling-server）
- `/api/imodels/:id/retry` 路由保留，内部改调 HUB requeue：服务账号 JWT（复用 T1.2 hubAuthClient 模式——MS 侧即 ServiceAccountAuthClient）+ `X-API-Key: config.IMODELHUB_API_KEY`。MS config schema **新增必填字段** `IMODELHUB_API_KEY: z.string().min(32)`（根 .env 与 generate-env 已写入该变量，MS 只是此前未消费；`.env.example` 注释补共享说明）。
- HUB 409 透传 FE（"已初始化不可重试"）；HUB 不可达 → 502。
- **删除 `WEBAGENT_URL` 全部引用**——MS→WA HTTP 边消失的硬证据。

### WA（webhook-agent）
- 删除 `/baseline/retry/:iModelId` 路由与 handler；`isValidAgentApiKey` 随最后一个调用点消失而删除。
- `luban-cad/scripts/regenerate-baseline.ts`、`check-imodel-status.ts`：直调 WA 改直调 HUB requeue（`X-API-Key`）。

## 2. WA 转发至少一次投递

### forwardQueueStore（新 `webhook-agent/src/forwardQueueStore.ts`）
- 条目 `{ id: string; event: ProcessedEvent; attempts: number; nextRetryAt: number }`；文件 `data/forward-queue.json`。
- 接口：`enqueue(event)`（入队即持久化）、`dequeueDue(now)`（取到期条目并原子标 in-flight）、`markDelivered(id)`（出队+压实持久化）、`markFailed(id, delayMs)`（attempts+1、退避 nextRetryAt）、`pendingCount()`、`drainOnBoot()`。
- 损坏容错：warn + 空队（同 processedEventsStore）。

### forwarder 改造
- 内存 `_retryQueue`/`_pendingEvents` **整体替换**为 store。
- 投递成功 `markDelivered`；失败 `markFailed`（指数退避：base 1s，×2，封顶 60s）；周期 tick 从 store 取 due；启动 `drainOnBoot` 重放积压。
- T2.1 修复语义保留且强化：放弃条目不再蒸发——留 store 无限退避重试。

### 可观测（T2.1 遗留）
- 周期 tick：`pendingCount()>0` → `logger.warn`（含最老条目等待时长）。
- `/health` 暴露 `pendingForwards`。

### 幂等前提（约束，改 MS 下列路由时必须保持）
- MS `/api/webhook/events` = log+ack（重复投递无副作用）；进度 POST = 幂等覆写。至少一次投递的安全性依赖此。

## 3. /ws 推送激活

### 契约（@luban-cad/shared）
- `IModelProgressEvent = { type: 'imodel-progress'; iModelId: string } & IModelProgressPayload`（webhooks/types.ts 本地扩展区）。

### MS 广播
- `registerProgressHandler` 回调：先更新 iModelProgressMap，后向全部 `wsClients` 广播 `JSON.stringify(progressEvent)`；单连接 send 失败 try/catch 忽略。

### FE 订阅
- 新 `features/imodel/hooks/useImodelProgressStream.ts`：ws 连接（复用 JWT query 鉴权；cookie 化属 T1.4）；onmessage 过滤本类型；断线指数退避重连（1s 起，封顶 30s）；30s 无消息视为陈旧；返回 `{ progressByIModel, live }`。
- imodel 列表页：`live===true` 用推送即时更新、关闭 `refetchInterval`；`false` 回退 5s 轮询。
- 删除死代码：`apps/web/shared/api/rpcClient.ts` 的 `setupWebSocket` 及其测试（被真订阅取代）。
- 编辑器内轮询（EditorBriefcaseStatus）不在本轮范围。

## 4. 测试与验收

| 组件 | 用例 |
|---|---|
| HUB requeue | failed→notInitialized 入列表；initialized→409；不存在→404 |
| MS retry | 转调 HUB requeue（URL/key/JWT 断言）；409 透传；不可达→502 |
| forwardQueueStore | enqueue 即持久化；dequeueDue 到期过滤；markDelivered 压实；markFailed 退避；损坏→空队；重启 round-trip |
| forwarder(store) | 首投清队；失败退避重投；重启重放积压；pending 告警 |
| MS 广播 | 进度回调→全员收到契约形状消息 |
| FE 钩子+列表页 | 解析入 Map；忽略他类型；断线重连；live 翻转；轮询开关随 live |

**验收**：
1. `grep WEBAGENT_URL modeling-server/src` = 0（无环硬证据）
2. 断电不丢：store round-trip + 「MS 停机→积压→恢复→送达」forwarder 测试
3. 推送级到达：FE 组件测试 live 推送下轮询关闭；全栈手动冒烟归生产门禁
4. retry 链路前三段单测覆盖；第四段（WA 拾取）归全栈冒烟

**不做**：WS cookie 鉴权（T1.4）；编辑器内轮询；HUB webhook `active` 语义自查（T2.4）。
