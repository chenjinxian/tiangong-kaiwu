## 1. SolveSpace GCS

### 技术架构

```
┌─────────────────────────────────────────────────────────┐
│                    SolveSpace GCS                        │
├─────────────────────────────────────────────────────────┤
│  核心算法: Dogleg (Powell's Dog Leg Method)              │
│  数值库: Eigen3 (矩阵运算)                                │
│  求解维度: 2D/3D 通用                                    │
│  语言: C++                                               │
└─────────────────────────────────────────────────────────┘
```

**求解流程**:
1. 将约束转化为非线性方程组 `f(x) = 0`
2. 计算 Jacobian 矩阵 `J = ∂f/∂x`
3. 使用 Dogleg 方法迭代求解:
   - 结合 Newton-Raphson 和梯度下降
   - 自适应步长控制
   - 处理 rank-deficient Jacobian

### 性能基准

| 指标 | 数值 | 说明 |
|------|------|------|
| **求解速度** | 1-10ms | 简单草图 (<20个约束) |
| **求解速度** | 10-50ms | 中等草图 (20-100个约束) |
| **求解速度** | 50-200ms | 复杂草图 (100-500个约束) |
| **收敛成功率** | ~95% | 合理约束条件下 |
| **内存占用** | <10MB | 求解器核心 |

### 稳定性分析

**优点**:
- ✅ **Dogleg算法稳健**: 在大多数初始猜测下收敛
- ✅ **开源验证**: 10+年实际使用，社区持续改进
- ✅ **自动处理过约束**: 能识别并报告冗余约束
- ✅ **数值稳定性**: 使用双精度浮点，Eigen3优化

**缺点**:
- ❌ **局部极小值**: 可能收敛到非预期的解
- ❌ **初始猜测敏感**: 复杂约束需要好的初始值
- ❌ **无全局优化**: 不能保证找到全局最优解

**典型失败场景**:
```
1. 循环依赖约束: A约束B，B约束C，C约束A
2. 几乎退化的情况: 三点几乎共线但要求共圆
3. 过度约束: 用户不小心添加了矛盾约束
4. 病态Jacobian: 约束矩阵接近奇异
```

### 约束支持

| 约束类型 | 2D | 3D | 说明 |
|----------|----|----|------|
| 重合 (Coincident) | ✅ | ✅ | 点在线上/点重合 |
| 距离 (Distance) | ✅ | ✅ | 点-点/点-线/线-线 |
| 角度 (Angle) | ✅ | ✅ | 线-线/面-面 |
| 水平/垂直 | ✅ | ✅ | 特定方向约束 |
| 平行 (Parallel) | ✅ | ✅ | 线-线/面-面 |
| 垂直 (Perpendicular) | ✅ | ✅ | 线-线/线-面 |
| 相切 (Tangent) | ✅ | ✅ | 圆-线/圆-圆/曲面 |
| 等长/等径 (Equal) | ✅ | ✅ | 多元素等值 |
| 对称 (Symmetric) | ✅ | ✅ | 关于点/线/面对称 |
| 固定 (Fix) | ✅ | ✅ | 锁定位置 |
| 共线 (Collinear) | ✅ | ✅ | 多点共线 |
| 同心 (Concentric) | ✅ | ✅ | 圆/弧/圆柱共轴 |
| 比例 (Ratio) | ❌ | ❌ | 不支持 |

| 指标 | 数值 | vs SolveSpace |

### 稳定性分析

**显著优势**:
- ✅ **商业级稳定性**: 20+年工业验证
- ✅ **智能初始猜测**: 自动计算合理的初始值
- ✅ **全局优化**: 部分约束支持全局最优

**商业优势**:

## SolveSpace 深度分析

### 算法细节

**Dogleg 方法**:
```python
# 伪代码
def dogleg_solve(f, J, x0, max_iter=100):
    x = x0
    for i in range(max_iter):
        fx = f(x)
        Jx = J(x)
        
        # 计算 Cauchy 点 (梯度下降)
        g = Jx.T @ fx
        alpha = (g.T @ g) / (g.T @ Jx.T @ Jx @ g)
        cauchy = -alpha * g
        
        # 计算 Newton 步
        try:
            newton = -np.linalg.solve(Jx.T @ Jx, g)
        except:
            newton = cauchy  # 退化时使用梯度
        
        # Dogleg 路径
        if np.linalg.norm(newton) < trust_radius:
            step = newton
        elif np.linalg.norm(cauchy) >= trust_radius:
            step = trust_radius * cauchy / np.linalg.norm(cauchy)
        else:
            # 在 Cauchy 和 Newton 之间插值
            step = dogleg_interpolate(cauchy, newton, trust_radius)
        
        # 更新
        x_new = x + step
        if convergence_check(x, x_new, fx):
            return x_new
        
        x = x_new
    return x
```

### 数值稳定性措施

1. **Jacobian 秩检查**: 检测约束是否独立
2. **条件数监控**: 检测病态问题
3. **自适应阻尼**: 在困难情况下自动调整步长
4. **多重启动**: 从多个初始点尝试求解

## 针对 Open Cloud CAD 的建议

### 推荐方案: SolveSpace GCS (WASM版)

**决策依据**:

1. **性能足够**: 
   - 大多数零件草图 < 100 个约束
   - 50ms 内完成求解，用户体验可接受
   - 拖拽操作能实时响应

2. **免费开源**:
   - 无许可费用
   - 可定制修改
   - 社区活跃

3. **功能完整**:
   - 支持所有必要约束类型
   - 2D/3D 都支持
   - 稳定性已验证

4. **技术可行性**:
   - 已有WASM编译方案
   - C API清晰
   - 与iTwin.js可集成

### 风险缓解

**风险1: 复杂零件性能不足**
- 缓解: 实施LOD策略，简化显示时减少约束
- 缓解: 异步求解，不阻塞UI

**风险2: 求解失败率较高**
- 缓解: 智能初始猜测算法
- 缓解: 友好的错误提示，引导用户调整约束

**风险3: WASM包体积大**
- 缓解: 仅编译核心求解器，剔除UI代码
- 缓解: 预估体积500KB-1MB，可接受
